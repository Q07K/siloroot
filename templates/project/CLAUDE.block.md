## SiloRoot 작업 공간

이 폴더는 SiloRoot 프로젝트 작업 공간이다. 마크다운 파일이 원본이고, 사람은 뷰어 화면으로, AI는 파일로 같은 내용을 본다. 이 블록(`siloroot:start`부터 `siloroot:end`까지)은 `/siloroot:init`이 관리한다. 블록 밖은 자유롭게 고친다.

### 경로와 검색

이 작업 공간의 문서는 프로젝트의 `.siloroot/` 폴더 안에 있다. 프로젝트 맨 위의 `CLAUDE.local.md`가 이 파일을 불러온다.

- 이 블록과 문서에 적힌 경로(아래 표의 경로, `related` 값, 백틱 경로)는 모두 `.siloroot/` 기준이다. 파일을 열거나 만들거나 검색할 때만 앞에 `.siloroot/`를 붙인다. 문서 안에 경로를 적을 때는 붙이지 않는다.
- `shared/`는 팀과 나눌 수 있는 영역이라 바깥 코드 저장소의 git에 보인다. 올릴지는 사용자가 커밋할 때 고른다. AI는 묻지 않고 커밋하지 않는다.
- `shared/` 밖(`private/`, 이 파일, 설정)은 git에서 빠져 있다(`.git/info/exclude`). 프로젝트 맨 위의 `.ignore`가 검색에서는 다시 찾게 하지만, SiloRoot 문서를 찾을 때는 검색 경로를 `.siloroot`로 준다.
- 팀의 `.gitignore`는 SiloRoot 때문에 고치지 않는다.

### 다른 작업 공간

공부 노트, 개인 아이디어, 사용자 정보, 글쓰기 규칙은 사람마다 하나인 홈(`{{home-path}}`)에 있다.

- 홈 문서는 `home:` 뒤에 홈 기준 경로를 적어 가리킨다. 예: `home:study/rust.md`. 파일을 열 때는 `home:`을 홈 경로로 바꾼다.
- 다른 프로젝트 문서는 `<이름>:` 뒤에 그 프로젝트의 `.siloroot/` 기준 경로를 적는다. 예: `앱:shared/issues/port-in-use.md`. 이름과 경로는 `~/.siloroot/user.json`에 있다.
- `related` 값에도, 백틱 경로에도 같은 꼴을 쓴다.
- 방향: 공유 문서(`shared/`)는 팀원이 볼 수 없는 문서(`private/`, `home:`)를 가리키지 않는다. 뷰어의 속성 점검이 경고한다.

### 자리

| 자리 | 경로 | 무엇이 있나 |
| --- | --- | --- |
| 이슈 | `shared/issues/` | 겪은 문제와 원인, 해결. 이슈 하나에 파일 하나 |
| 제품 아이디어 | `shared/ideas/` | 이 프로젝트에서 만들 것. 아이디어 하나에 파일 하나 |
| 결정 | `shared/decisions/` | 따로 남길 결정 하나에 파일 하나 |
| 설계 | `shared/design/` | 설계 문서 |
| 로드맵 | `shared/roadmap/` | 만드는 순서와 계획 |
| 컨벤션 | `shared/conventions/` | 팀이 따르는 약속과 정책 |
| 작업 기록 | `private/log/` | 작업 기록(`changelog.md`)과 사용자 확인이 필요한 것(`open-questions.md`) |
| 원자료 | `private/sources/` | 받은 자료, 회의 메모처럼 다른 문서의 근거가 되는 원본 |
| 프로젝트 메모, 논의 | `private/notes/`, `private/discussions/` | 개인 메모와, 사용자와 의견을 주고받은 기록 |
| 뷰어 댓글 | `private/feedback/` | 이 작업 공간 문서에 뷰어에서 남긴 댓글 |
| 공부 노트, 개인 아이디어 | `home:study/`, `home:ideas/` | 홈에 둔다 |
| 후보 | `home:feedback/` | 글쓰기 규칙 후보, 사용자 정보 후보. 어느 프로젝트에서 생겨도 홈에 둔다 |
| 사용자 정보, "나" 코멘트, 글쓰기 규칙 | `home:profile.md`, `home:ai-comment.md`, `home:writing-guide.md` | 홈에 둔다 |
| 설정 | `config.json`, `state/` | 설정과 뷰어 생성물. 직접 고치지 않는다 |

### 규칙

- 모든 마크다운 문서 맨 위에 속성(`type`, `status`)을 적는다. 값과 폴더별 규칙은 `metadata-guide.md`에 있다.
- 다른 문서는 폴더 맨 위 기준 경로를 백틱으로 적는다. 뷰어가 이것을 연결로 읽는다.
- 기술 질문을 공부할 때는 `/siloroot:note`, "검증해 줘"라고 하면 `/siloroot:verify`를 따른다.
- 훅이 "[SiloRoot] 처리할 일"을 알리면 지금 요청을 끝낸 뒤 `/siloroot:feedback`을 따른다.
- 글을 쓰거나 고치기 전에 홈의 글쓰기 규칙(`{{writing-guide}}`)을 읽는다. 사용자가 표현을 지적하면 규칙 후보로 남긴다.

### 사용자 정보

사용자가 승인한 작업 습관과 선호는 홈의 `profile.md`에 있고 아래 줄로 불러온다. 이 블록의 다른 규칙과 부딪히면 이 파일을 먼저 따르지 말고 사용자에게 묻는다.

{{profile-import}}

- 일하면서 습관이나 선호가 보이거나, 사용자가 "앞으로", "항상", "매번"처럼 앞으로도 그러라고 직접 말하면 `/siloroot:feedback`의 D 절차로 후보(`trait`) 파일부터 홈 `feedback/`에 만든다.
- 보인 습관은 사용자가 승인하기 전에는 쓰지 않는다. 직접 말한 것은 그 말을 승인으로 보고 같은 턴에 E 절차로 `profile.md`에 넣는다.
- `profile.md`에는 E 절차로만 줄을 더한다. 근거 칸에는 후보 파일 경로를 적는다. 후보 파일 없이 바로 쓰지 않는다.

### 흐름 나누기

한 대화가 프로젝트, 공부, 아이디어, 결정 사이를 오가도 된다. 대화는 흐르게 두고 문서를 관심사별로 나눈다.

- 새 내용이 나오면 종류부터 본다. 개념 이해는 공부, 겪은 문제는 이슈, 만들고 싶은 것은 아이디어, 정한 것은 결정이다. 작업 중에 나온 "X와 Y 차이는?", "X가 뭐야?" 같은 개념 질문도 공부다. 작업의 연장으로 보고 채팅에서 답만 하고 넘어가지 않는다.
- 프로젝트에서 생긴 공부는 둘로 나눈다. 개념은 홈 공부 노트(`home:study/`)에, 이 프로젝트에서 겪은 사건은 이슈(`shared/issues/`)에 둔다. 홈 노트의 `related`에 `<이 프로젝트 이름>:shared/issues/...`를 적어 잇는다. 이슈 쪽은 홈을 가리키지 않는다.
- 이 프로젝트에서 만들 것은 `shared/ideas/`, 이 프로젝트와 상관없는 개인 아이디어는 `home:ideas/`에 둔다.
- 지금 이야기와 종류가 다른 내용이 나오면 한 번만 나와도 그 종류의 자리에 새 문서를 만든다. 예: 프로젝트 작업 중의 개념 질문은 홈 공부 노트로.
- 종류가 같아도 관심사가 다르면 나눈다. 따로 설명할 수 있는 내용이고 사용자가 정했거나, 만들기 시작했거나, 이어서 이야기했으면 한 번만 나와도 새 문서로 둔다. 다른 문서의 한 절로 붙여 두면 뷰어에 점과 연결이 생기지 않는다.
- 정하지도 않고 한 번 스친 것만 지금 문서에 한 줄로 두고, 나중에 이어서 이야기하면 그때 빠짐없이 옮긴다. 공부끼리 나누는 자세한 법과 노트 하나의 크기는 `/siloroot:note`의 "노트 나누기"에 있다.
- 사용자가 묻지 않은 개념이나 정하지 않은 일로 문서를 만들지 않는다. 답하다 나온 이웃 개념은 지금 문서의 "다음에 볼 것"에 한 줄로 적는다.
- 새 문서 제목 아래에 어느 문서의 어떤 이야기에서 나왔는지 한 줄 적고, 두 문서의 `related`에 서로를 넣는다(방향 원칙에 걸리면 공유 문서 쪽은 빼고 적는다). 원래 문서의 그 자리에는 한두 줄 요약과 경로를 남긴다.
- 같은 설명은 한 곳에만 두고 다른 문서에서는 가리킨다.
- 나누는 일은 묻지 않고 하고, 답을 마칠 때 이번에 만들거나 나눈 문서를 한 줄로 알린다. 사용자가 합치라고 하면 합친다.
- 아이디어를 만들기 시작하면 문서를 그대로 두고 `status`를 `진행 중`으로 바꾼다. 그때부터 따로 남길 결정은 `shared/decisions/`, 설계는 `shared/design/`, 만드는 순서와 계획은 `shared/roadmap/`에 둔다. 작은 결정은 `private/log/changelog.md`에 한 줄로 쓴다.

### 마칠 때

- 한 일을 `private/log/changelog.md`에 날짜와 함께 한 줄로 남긴다.
- 사용자 확인이 필요한 것은 `private/log/open-questions.md`에 더한다.
- 문서를 만들었거나 속성을 고쳤으면 `metadata-guide.md`의 값과 폴더 규칙에 맞는지 다시 본다. 사용자는 뷰어의 "객체 > 속성 점검" 화면에서 경고를 볼 수 있다(뷰어는 열 때마다 새로 만들어진다).
