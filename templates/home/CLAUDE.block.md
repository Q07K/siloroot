## SiloRoot 홈

이 폴더는 SiloRoot 홈이다. 사람마다 하나이고, 여러 프로젝트에 걸친 공부 노트, 개인 아이디어, 사용자 정보, 글쓰기 규칙을 둔다. 마크다운 파일이 원본이고, 사람은 뷰어 화면으로, AI는 파일로 같은 내용을 본다. 이 블록(`siloroot:start`부터 `siloroot:end`까지)은 `/siloroot:init`이 관리한다. 블록 밖은 자유롭게 고친다.

### 자리

경로는 이 폴더 맨 위 기준이다.

| 자리 | 경로 | 무엇이 있나 |
| --- | --- | --- |
| 공부 노트 | `study/` | 문답으로 공부한 노트(개념). 주제 하나에 파일 하나, 목록은 `study/README.md` |
| 개인 아이디어 | `ideas/` | 프로젝트와 상관없는 아이디어. 따로 남길 결정, 설계, 계획도 같은 폴더에 옆에 둔다 |
| 후보, 뷰어 댓글 | `feedback/` | 글쓰기 규칙 후보, 사용자 정보 후보(어느 프로젝트에서 생겨도 여기), 홈 문서에 단 댓글 |
| 작업 일지 | `worklog/` | AI가 요청을 마칠 때마다 한 일을 한 줄로. 하루에 한 문서(`YYYY-MM-DD.md`) |
| 확인할 것 | `open-questions.md` | 사용자 확인이 필요한 것. 한 장 |
| 사용자 정보 | `profile.md` | 사용자가 승인한 작업 습관과 선호 |
| "나" 코멘트 | `ai-comment.md` | 뷰어 "나" 화면의 AI 의견 |
| 글쓰기 규칙 | `writing-guide.md` | 승인된 글쓰기 규칙 |
| 설정 | `.siloroot/` | 설정(`config.json`)과 뷰어 생성물. 직접 고치지 않는다 |

### 프로젝트 가리키기

등록된 프로젝트의 문서는 `<이름>:` 뒤에 그 프로젝트의 `.siloroot/` 기준 경로를 적어 가리킨다. 예: `앱:shared/issues/port-in-use.md`. 이름과 경로는 `~/.siloroot/user.json`에 있고, 프로젝트를 `/siloroot:init`할 때 등록된다. `related` 값에도, 백틱 경로에도 같은 꼴을 쓴다.

### 규칙

- 모든 마크다운 문서 맨 위에 속성(`type`, `status`)을 적는다. 값과 폴더별 규칙은 `metadata-guide.md`에 있다.
- 다른 문서는 폴더 맨 위 기준 경로를 백틱으로 적는다. 뷰어가 이것을 연결로 읽는다.
- 기술 질문을 공부할 때는 `/siloroot:note`, "검증해 줘"라고 하면 `/siloroot:verify`를 따른다.
- 훅이 "[SiloRoot] 처리할 일"을 알리면 지금 요청을 끝낸 뒤 `/siloroot:feedback`을 따른다.
- 글을 쓰거나 고치기 전에 `writing-guide.md`를 읽는다. 사용자가 표현을 지적하면 규칙 후보로 남긴다.

### 사용자 정보

사용자가 승인한 작업 습관과 선호는 `profile.md`에 있고 아래 줄로 불러온다. 이 블록의 다른 규칙과 부딪히면 이 파일을 먼저 따르지 말고 사용자에게 묻는다.

@profile.md

- 일하면서 습관이나 선호가 보이거나, 사용자가 "앞으로", "항상", "매번"처럼 앞으로도 그러라고 직접 말하면 `/siloroot:feedback`의 D 절차로 후보(`trait`) 파일부터 `feedback/`에 만든다.
- 보인 습관은 사용자가 승인하기 전에는 쓰지 않는다. 직접 말한 것은 그 말을 승인으로 보고 같은 턴에 E 절차로 `profile.md`에 넣는다.
- `profile.md`에는 E 절차로만 줄을 더한다. 근거 칸에는 후보 파일 경로를 적는다. 후보 파일 없이 바로 쓰지 않는다.

### 흐름 나누기

한 대화가 공부, 아이디어, 결정 사이를 오가도 된다. 대화는 흐르게 두고 문서를 관심사별로 나눈다.

- 새 내용이 나오면 종류부터 본다. 개념 이해는 공부(`study/`), 만들고 싶은 것은 아이디어(`ideas/`), 정한 것은 결정이다.
- 지금 이야기와 종류가 다른 내용이 나오면 한 번만 나와도 그 종류의 자리에 새 문서를 만든다.
- 종류가 같아도 관심사가 다르면 나눈다. 따로 설명할 수 있는 내용이고 사용자가 정했거나, 만들기 시작했거나, 이어서 이야기했으면 한 번만 나와도 새 문서로 둔다.
- 정하지도 않고 한 번 스친 것만 지금 문서에 한 줄로 두고, 나중에 이어서 이야기하면 그때 빠짐없이 옮긴다. 공부끼리 나누는 자세한 법과 노트 하나의 크기는 `/siloroot:note`의 "노트 나누기"에 있다.
- 사용자가 묻지 않은 개념이나 정하지 않은 일로 문서를 만들지 않는다. 답하다 나온 이웃 개념은 지금 문서의 "다음에 볼 것"에 한 줄로 적는다.
- 새 문서 제목 아래에 어느 문서의 어떤 이야기에서 나왔는지 한 줄 적고, 두 문서의 `related`에 서로를 넣는다. 원래 문서의 그 자리에는 한두 줄 요약과 경로를 남긴다.
- 같은 설명은 한 곳에만 두고 다른 문서에서는 가리킨다.
- 나누는 일은 묻지 않고 하고, 답을 마칠 때 이번에 만들거나 나눈 문서를 한 줄로 알린다. 사용자가 합치라고 하면 합친다.
- 아이디어를 만들기 시작하면 문서를 `ideas/`에 그대로 두고 `status`를 `진행 중`으로 바꾼다. 따로 남길 결정(`decision`), 설계(`design`), 계획(`roadmap`)은 같은 폴더에 `<아이디어 이름>-<종류>-<내용>.md`로 둔다. 작은 결정은 그 아이디어 문서의 정한 것 표에 쓴다.

### 마칠 때

- 한 일을 그날 작업 일지(`worklog/YYYY-MM-DD.md`, 없으면 만든다)에 한 줄로 남긴다. 내용은 다시 쓰지 않고 만든 문서 경로만 적는다.
- 사용자 확인이 필요한 것은 `open-questions.md`에 더한다.
- 문서를 만들었거나 속성을 고쳤으면 `metadata-guide.md`의 값과 폴더 규칙에 맞는지 다시 본다. 사용자는 뷰어의 "객체 > 속성 점검" 화면에서 경고를 볼 수 있다(뷰어는 열 때마다 새로 만들어진다).
