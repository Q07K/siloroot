# 문서 속성 가이드

문서를 만들거나 고칠 때 이 파일을 따른다. 모든 문서 맨 위에 속성(프론트매터)을 적어 사람과 AI가 문서를 객체로 다루게 하는 약속이다. 뷰어가 이 속성을 읽어 객체 목록과 연결을 만들고, 약속에 어긋나면 "속성 점검"에 경고를 띄운다.

## 1. 원칙

| 원칙 | 내용 |
| --- | --- |
| 모든 문서에 종류를 적는다 | 마크다운 문서는 모두 `type`과 `status`를 가진다 |
| 객체 종류는 문서 하나가 객체 하나일 때만 쓴다 | 아이디어, 공부 노트, 결정처럼 문서 자체가 객체면 객체 종류를, 장부나 기록처럼 안에 객체가 여러 개면 문서 종류를 쓴다 |
| 속성은 본문을 대신하지 않는다 | 속성에는 분류와 상태만 적는다. 설명은 본문에 쓴다 |
| 같은 말을 두 곳에 쓰지 않는다 | 상태를 속성에 적었으면 본문에 "상태: …" 줄을 따로 두지 않는다 |
| 정해진 값만 쓴다 | `type`과 `status`는 2절 표의 값 중에서 고른다 |
| 다른 문서는 폴더 맨 위 기준 경로로 가리킨다 | 본문에서는 `` `02-study/radius.md` ``처럼 백틱으로, 함께 봐야 하는 문서는 `related`에도 적는다 |

## 2. 속성 목록

```markdown
---
type: study
status: 검증 전
created: {{date}}
related: [03-ideas/viewer.md]
tags: [CSS]
---
```

| 속성 | 필수 | 값 | 뜻 |
| --- | --- | --- | --- |
| `type` | 필수 | 아래 표 | 무슨 문서, 무슨 객체인가 |
| `status` | 필수 | 아래 표 | 지금 어떤 상태인가 |
| `title` | 문서에 `#` 제목이 없을 때 | 짧은 이름 | 뷰어와 그래프에 보일 이름 |
| `created` | 권장 | `YYYY-MM-DD` | 처음 적은 날 |
| `related` | 선택 | 경로 목록 `[a.md, b/c.md]` | 함께 봐야 하는 문서. 뷰어가 연결선으로 그린다 |
| `tags` | 선택 | 짧은 낱말 목록 | 검색용. 3개 이내 |

### 객체 종류

| type | 무엇 | status 값 |
| --- | --- | --- |
| `idea` | 아이디어. 만들기 시작한 프로젝트도 `진행 중`으로 여기에 둔다 | 아이디어, 진행 중, 보류, 접음, 완료 |
| `study` | 문답으로 검증하는 공부 노트 | 검증 전, 부분, 통과 |
| `decision` | 따로 남길 결정 하나 | 제안, 확정, 바뀜 |
| `project` | 진행 중인 프로젝트의 설명 문서. 기본으로는 쓰지 않고 `idea`의 `진행 중`으로 대신한다 | 진행 중, 보류, 완료 |
| `feedback` | 뷰어에서 남긴 댓글 하나 | 대기, 진행 중, 완료, 안 함 |
| `rule` | 글쓰기 규칙 후보 하나 | 제안, 승인, 거절, 반영 |

### 문서 종류

| type | 무엇 | status 값 |
| --- | --- | --- |
| `guide` | 작업 규칙 | 사용 중, 보관 |
| `index` | 폴더 안내와 목차 | 사용 중, 보관 |
| `ledger` | 객체 여러 개를 모은 장부 | 사용 중, 보관 |
| `log` | 시간순 기록 | 사용 중, 끝남 |
| `note` | 메모 | 사용 중, 보관 |

쓰는 법:

- 속성 한 줄에 `이름: 값` 하나. 들여쓰기 구조는 쓰지 않는다.
- 값 안에 `: `(쌍점과 공백)이 있으면 값 전체를 큰따옴표로 감싼다.
- 목록은 대괄호 안에 쉼표로 적는다.
- 프론트매터는 파일의 맨 첫 줄에서 시작한다.

## 3. 폴더별 규칙

| 폴더 | type | 비고 |
| --- | --- | --- |
| `02-study/` | `study` (`README.md`는 `index`) | `status`는 이해도다. `02-study/README.md` 주제 목록의 이해도와 같게 맞춘다 |
| `03-ideas/` | `idea`, 결정은 `decision` (`README.md`는 `index`) | 아이디어 하나에 파일 하나. 만들기 시작하면 `status`만 `진행 중`으로 바꾸고 옮기지 않는다. 따로 남길 결정은 `<아이디어 이름>-decision-<내용>.md`로 옆에 둔다 |
| `04-feedback/` | `feedback` 또는 `rule` (`README.md`는 `index`) | 형식은 `04-feedback/README.md`를 따른다 |
| `01-log/` | 기록은 `log`, `open-questions.md`는 `ledger` | |
| 맨 위 | 규칙은 `guide`, `README.md`는 `index` | |

## 4. 장부 안의 객체

| 파일 | 객체 | 지켜야 할 형식 |
| --- | --- | --- |
| `01-log/open-questions.md` | 미해결 질문 | `## 구분` 아래 `- [ ] **제목**: 내용`. 끝내면 `[x]`로 바꾸거나 줄을 지운다 |

## 5. AI가 할 일

- 새 문서는 3절에서 폴더 규칙을 찾아 프론트매터부터 쓰고, `created`는 오늘 날짜로 적는다.
- 상태가 바뀌었으면 `status`만 고친다. 공부 노트의 `status`를 고쳤으면 `02-study/README.md`의 이해도도 맞춘다.
- 사용자가 고친 속성 값은 묻지 않고 되돌리지 않는다.
- 마친 뒤 위 값과 폴더 규칙에 맞는지 다시 본다. 뷰어의 "객체 > 속성 점검" 화면에도 같은 경고가 나온다.
