# SiloRoot

[English](README.md) | **한국어**

도구마다 흩어진 기록(사일로)을 마크다운 폴더 하나(뿌리)로 모으는 Claude Code 플러그인이다. 폴더의 마크다운 파일이 원본이고, 사람은 로컬 뷰어 화면으로, AI는 파일로 같은 내용을 본다. 아직 초기 버전(v0)이다.

## 준비물

- Claude Code
- `PATH`에 잡힌 Node.js (훅과 뷰어가 `node`로 실행된다)

## 설치

```powershell
claude plugin marketplace add Q07K/siloroot
cd <작업 공간으로 쓸 폴더>
claude plugin install siloroot@siloroot --scope project
```

저장소를 내려받아 쓰려면 첫 줄 대신 `claude plugin marketplace add <내려받은 경로>`를 쓴다.

그 폴더에서 Claude Code를 열고 `/siloroot:init`을 실행한다.

### Claude에게 맡기기

명령을 직접 치지 않고 Claude Code에 말로 맡겨도 된다. 데스크톱 앱처럼 터미널을 따로 열지 않고 쓰는 곳에서 편하다. 작업 공간으로 쓸 폴더를 Claude Code에서 프로젝트로 열고 이렇게 말한다.

```text
이 프로젝트에 SiloRoot 플러그인을 설치해 줘. 마켓플레이스는 Q07K/siloroot야.
```

- Claude가 지금 열린 프로젝트 폴더에서 위의 두 명령을 실행한다. 폴더 경로를 말하거나 `cd`할 필요는 없다. 권한 설정에 따라 실행 승인을 한 번 눌러야 할 수 있다.
- 설치를 부탁한 대화에는 적용되지 않는다. 설치가 끝나면 같은 프로젝트에서 새 세션을 열고 `/siloroot:init`을 실행한다.
- 업데이트도 같다. "이 프로젝트의 SiloRoot 플러그인 업데이트해 줘"라고 하면 Claude가 `claude plugin update siloroot@siloroot --scope project`를 실행한다. 적용하려면 새 세션을 연다.

### Codex에서 쓰기

이미 초기화한 SiloRoot 작업 공간에서 Codex도 SiloRoot 작업 규칙을 따르고, Codex의 셸 읽기와 `apply_patch` 편집을 연결 그래프의 흔적으로 볼 수 있다.

```powershell
codex plugin marketplace add Q07K/siloroot
codex plugin add siloroot@siloroot
```

작업 중인 저장소 사본을 시험할 때는 첫 줄에 GitHub 이름 대신 그 폴더의 절대 경로를 넣는다. Codex 데스크톱은 **설정 → Hooks**, CLI는 `/hooks`에서 SiloRoot 훅을 검토하고 신뢰할 수 있다. 작업 공간에서 새 세션을 열고, 실행 중인 SiloRoot 뷰어에서 **연결 → 흔적**을 본다. [Codex 훅 문서](https://developers.openai.com/codex/hooks#review-and-trust-hooks)

뷰어가 꺼져 있으면 `node "<SiloRoot 플러그인 폴더>/viewer/serve.mjs" "<작업 공간 폴더>"`로 켠다. 파일 흔적은 현재 Codex 세션에서 새 메시지를 보내면 비워진다.

모양 3 이상 프로젝트에서는 Codex 세션도 시작할 때 Claude Code와 같은 방식으로 프로젝트 컨벤션을 받는다(아래 "뷰어"의 훅 설명). Codex는 훅 출력을 약 2,500토큰으로 제한하므로, 3,000자를 넘으면 본문 대신 컨벤션 문서 목록을 넣는다.

Codex는 `CLAUDE.local.md`를 읽지 않아서, SiloRoot 작업 규칙(`.siloroot/CLAUDE.md`, 홈은 `CLAUDE.md`)을 두 길로 넣는다.

- 세션 시작 훅이 규칙 본문과, 그 안의 `@` 줄이 가리키는 사용자 정보를 맥락에 넣는다. 이 훅은 출력 한도(`additionalContextLimit`)를 12,000토큰으로 올려 둔다. 훅을 신뢰해야 돈다.
- `/siloroot:init`과 `/siloroot:update`가 Codex 전역 지침(`~/.codex/AGENTS.md`, `CODEX_HOME`을 따른다. `AGENTS.override.md`가 있으면 그 파일)에 SiloRoot 관리 블록을 넣는다. SiloRoot 폴더에서는 규칙 파일을 먼저 읽고, "문서로 써 줘"는 마크다운 문서로 만들라는 짧은 안내다. 훅을 신뢰하지 않았을 때의 안전망이다. 블록 밖은 건드리지 않고, Codex 폴더가 없으면 만들지 않는다.

## 스킬

| 스킬 | 언제 |
| --- | --- |
| `/siloroot:init` | 폴더를 작업 공간으로 만든다. 없는 파일만 만들고 뷰어를 연다 |
| `/siloroot:note` | 기술 개념을 문답으로 공부한다. 공부 노트가 생기고 이어 적힌다. 질문이 옆 주제로 번지면 노트를 나누고 링크로 묶는다 |
| `/siloroot:verify` | "검증해 줘". Claude가 질문하고 판정해 검증 기록과 이해도를 갱신한다 |
| `/siloroot:feedback` | 뷰어에서 남긴 댓글과 웹 편집을 처리하고, Claude가 일하면서 본 작업 습관과 선호를 사용자 정보 후보로 남긴다. "앞으로 항상 …해 줘"라고 직접 말한 것도 후보를 먼저 만들고, 그 말을 승인으로 보아 사용자 정보(홈의 `profile.md`)에 넣는다. 홈에서 기다리는 후보까지 훅이 알려 준다 |
| `/siloroot:update` | 새 플러그인 버전을 받고(먼저 묻는다), 작업 공간과 홈의 관리 블록과 안내 문서를 맞추고, 뷰어 서버를 새 버전으로 바꾸고, 그 버전에서 무엇이 바뀌었는지 보인다. 새 버전이 나올 때마다 돌린다 |
| `/siloroot:migrate` | 예전 모양의 작업 공간을 새 모양으로 옮긴다(마이그레이션). 모양이 바뀌는 버전에서만 쓴다. 바뀌는 것을 먼저 보여 주고 승인받으며, 백업을 남겨 되돌릴 수 있다 |

한 대화가 공부, 아이디어, 결정, 프로젝트 사이를 오가도 된다. 대화는 흐르게 두고, Claude가 내용의 종류를 보고 알맞은 폴더에 문서를 나눠 서로 잇는다. 규칙은 작업 공간의 `CLAUDE.md` 블록에 들어간다.

## 만들어지는 폴더

SiloRoot의 작업 공간은 두 가지다(모양 4, 0.8.0부터).

- **프로젝트**: 프로젝트마다 `.siloroot/` 폴더 안에 둔다. 팀이 볼 수 있는 것은 공유 영역(`shared/`)에, 나만 보는 것은 개인 영역(`private/`)에 둔다.
- **홈**: 사람마다 하나. 기본 위치는 `<사용자 폴더>/siloroot-home`이다. 여러 프로젝트에 걸친 공부 노트, 개인 아이디어, 사용자 정보, 글쓰기 규칙을 둔다. 프로젝트에서 처음 `/siloroot:init`을 하면 위치를 묻고 만든다.

홈 위치와 프로젝트 목록은 `~/.siloroot/user.json`에 적힌다. 팀이 같이 쓰는 `CLAUDE.md`와 `.gitignore`는 고치지 않는다.

### 프로젝트

| 경로 | 내용 |
| --- | --- |
| `.siloroot/CLAUDE.md` | SiloRoot 표시 블록(자리 표와 규칙). 블록 밖은 자유 |
| `.siloroot/metadata-guide.md` | 프로젝트용 문서 속성 약속 |
| `.siloroot/shared/` | `roadmap.md`(만들기로 정한 것: 지금, 다음, 나중), `architecture.md`(지금 구조 한 장), `requirements/`(기능마다 요구사항), `ideas/`(제품 아이디어), `decisions/`(결정과 반영 상태), `design/`, `plans/`(구현 계획), `issues/`, `conventions/`(용어집 `glossary.md` 포함). `git status`에 보이고, 올릴지는 사용자가 고른다 |
| `.siloroot/private/` | `worklog/`(하루에 한 문서인 작업 일지), `open-questions.md`(확인할 것), `sources/`, `notes/`, `discussions/`, `feedback/`(뷰어 댓글) |
| `.siloroot/config.json`, `state/` | 설정(포트, 배치)과 뷰어 생성물 |
| `CLAUDE.local.md` | `@.siloroot/CLAUDE.md` 한 줄로 SiloRoot 규칙을 불러온다. 이미 있으면 표시 블록만 끝에 붙인다 |
| `.ignore` | git은 `.siloroot/`를 무시해도 Claude의 검색(ripgrep)은 찾게 한다(`!.siloroot/`). 생성물은 검색에서도 뺀다 |
| git 제외 목록(`.git/info/exclude`) | `shared/`를 뺀 `.siloroot/`와 `.ignore`, `CLAUDE.local.md`를 이 PC의 이 저장소에서만 커밋 대상에서 뺀다. git 저장소일 때만 쓴다 |

### 홈

| 경로 | 내용 |
| --- | --- |
| `CLAUDE.md`, `metadata-guide.md` | 홈의 규칙 블록과 속성 약속 |
| `study/` | 공부 노트와 주제 목록(이해도). 어느 프로젝트에서 배운 개념이든 여기에, 그 프로젝트에서 겪은 일은 그 프로젝트의 `shared/issues/`에 둔다 |
| `ideas/` | 개인 아이디어(사용자가 개인 아이디어라고 한 것)와 그 옆의 결정, 설계, 계획 |
| `feedback/` | 모든 프로젝트에서 생긴 글쓰기 규칙 후보와 사용자 정보 후보, 홈 문서에 단 댓글 |
| `worklog/`, `open-questions.md` | 하루에 한 문서인 작업 일지, 확인할 것 |
| `profile.md`, `ai-comment.md`, `writing-guide.md` | 승인한 작업 습관과 선호(모든 프로젝트의 규칙 블록이 불러온다), "나" 화면 코멘트, 글쓰기 규칙 |

- 자리 폴더마다 `README.md`가 있다. 무엇을 넣고 무엇을 넣지 않는지(그건 어디로), 파일 이름, 상태, 쓰는 틀이 적혀 있다. 뷰어 그래프는 문서가 없는 자리도 흐린 원으로 그린다.
- 대화에서 생기는 일마다 갈 문서가 정해져 있다: 정한 것은 결정 기록, 겪은 문제는 이슈, 측정값은 그 값으로 정한 결정 기록의 근거, 만들기로 한 것은 로드맵과 요구사항, 주제가 바뀌면 새 논의 기록. 규칙은 관리 블록의 "흐름 나누기"에 있다.
- 문서 안의 경로(`related`, 백틱 경로)는 그 작업 공간의 문서 뿌리(프로젝트는 `.siloroot/`) 기준이다. 홈 문서는 `home:study/a.md`, 다른 프로젝트 문서는 `<이름>:shared/issues/x.md`로 적는다. 이름은 `user.json`에 있다.
- 공유 문서는 팀원이 볼 수 없는 개인 문서나 홈 문서를 가리키지 않는다. 뷰어의 속성 점검이 경고한다.
- 홈 쓰기 허락: 홈은 프로젝트 밖이라 Claude Code가 홈에 쓸 때마다 허락을 물을 수 있다. init이 프로젝트의 `.claude/settings.local.json`(`permissions.additionalDirectories`)에 홈 폴더를 더할지 묻는다. 기본값은 더하기이고, 그 파일의 다른 설정은 그대로 둔다.
- `.git/info/exclude`는 PC마다 따로라서, 같은 프로젝트를 다른 PC에서 받으면 init을 한 번 더 실행한다. `shared/`가 든 저장소를 받은 팀원은 공유 문서를 그대로 받고, init이 나머지를 만든다.
- 예전 버전의 작업 공간(모양 1, 2. 공부 노트 폴더 같은 번호 붙은 폴더)은 그대로 동작한다. `/siloroot:update`가 한 칸씩 옮긴다: 0.7.0부터 모양 3으로, 0.8.0부터 모양 4로(업데이트 절).

템플릿과 스킬 문구는 지금 한국어로만 되어 있다.

## 업데이트

평소 업데이트는 `/siloroot:update` 하나다. 마켓플레이스에서 더 새 SiloRoot가 있는지 보고, 이 프로젝트의 플러그인을 올릴지 묻고, 작업 공간과 홈의 관리 블록과 안내 문서를 맞추고, 옛 버전으로 떠 있는 뷰어 서버를 새 버전으로 바꾸고(열린 뷰어 탭은 스스로 새로 읽는다), `CHANGELOG.md`에서 바뀐 것을 보인다. 새 스킬과 훅은 다음 세션부터 적용된다. 작업 공간 모양이 바뀌는 버전이면 `/siloroot:migrate`가 옮긴다. 부 버전(0.x.0)은 모양이 바뀔 때만 오르고, 나머지는 모두 패치(0.x.y)로 나온다.

세션을 시작할 때 모양이 뒤처졌으면(`/siloroot:migrate`) 또는 맞출 것이 있으면(`/siloroot:update`) 훅이 한 번 알린다. 버전 번호만 다르고 맞출 것이 없으면 알리지 않고 새 번호만 적는다. 작업 공간이 뒤처졌으면 세션을 시작할 때 훅이 한 번 알린다. 메시지마다 붙지는 않는다.

- 작업 공간은 `.siloroot/config.json`에 자기 모양 번호(`schema`)와 마지막으로 맞춘 플러그인 버전(`plugin`)을 적어 둔다.
- 모양이 바뀐 버전이면 `/siloroot:migrate`가 마이그레이션으로 옮긴다. 한 번에 한 칸씩 오르고, 한 칸을 올린 뒤 다음 칸을 다시 미리 보여 준다. 마이그레이션은 셋이다.
  - 모양 1(문서가 프로젝트 맨 위에 있는 예전 방식)에서 2(`.siloroot/` 안에 감싼 방식)로.
  - 모양 2에서 3으로(0.7.0). 프로젝트 문서를 `shared/`와 `private/`로 나누고, 공부 노트, 사용자 정보, 글쓰기 규칙, 규칙과 사용자 정보 후보는 홈으로 옮긴다. 홈이 없으면 고른 자리에 만든다. 문서마다 갈 곳을 보여 주고 목록을 한 번 승인받는다. 아이디어는 규칙으로 가를 수 없어 기본값이 `shared/ideas/`다. 개인 아이디어는 `home:ideas/`로 바꾸면 그 결정 문서와 그림도 따라간다. 옮긴 문서 안의 경로는 새 자리로 고친다(작업 공간 사이는 `home:…`, `<이름>:…`). 홈에 `profile.md`, `writing-guide.md`, `study/README.md`가 이미 있으면 덮어쓰지 않고 표 줄을 합친다. 홈에 같은 이름의 공부 노트가 있으면 묻는다. 커밋은 하지 않는다. `shared/`에서 무엇을 올릴지는 사용자가 고른다. 그다음 같은 스크립트로 홈도 맞춘다.
  - 모양 3에서 4로(0.8.0). 작업 기록(`changelog.md`)을 날짜 제목마다 `private/worklog/YYYY-MM-DD.md`로 나누고, 확인할 것은 `private/open-questions.md`로 옮긴다. 예전 `shared/roadmap/`의 문서는 기능마다의 구현 계획이라 `shared/plans/`로 옮기고, 로드맵 한 장(`shared/roadmap.md`)과 시스템 개요(`shared/architecture.md`), 자리마다 README를 새로 만든다. 아이디어 폴더 안의 결정, 설계, 계획 문서는 제자리로 옮기는데 그 목록을 한 번 승인받는다. 이슈 상태 `원인 찾음`은 `열림`으로, `안 함`은 `안 고침`으로 바꾼다. 옮긴 문서를 가리키던 경로는 홈과 등록된 프로젝트 문서까지 고친다. 홈은 `log/`를 `worklog/`와 `open-questions.md`로 바꾼다.
- 모양 3 이상 프로젝트의 세션 시작 알림은 홈이 뒤처졌을 때도 알린다.
- 바뀌는 것을 먼저 보여 주고, 사람이 고를 것(팀 `CLAUDE.md`의 블록 밖 내용, 맨 위 `.gitignore`, git에 커밋된 문서 등)은 하나씩 묻는다. 답 없이 기본값을 고르지 않는다.
- 옮기지 않고 지금 모양에 머물 수 있다. 그러면 관리 블록 맞추기만 받고, 그 모양 알림은 다시 나오지 않는다(`config.json`의 `hold`).
- 바꾸기 전에 `.siloroot/state/backups/`에 백업한다. "되돌려 줘"라고 하면 최신 백업부터 되돌린다(`/siloroot:migrate`. `/siloroot:update`의 맞추기도 여기서 되돌린다). 업데이트 뒤 고친 파일이 있으면 멈추고 묻는다. 모양을 바꾼 백업은 저절로 지우지 않고, 맞추기만 한 백업은 최근 5개만 남긴다.

## 뷰어

`http://127.0.0.1:<config.json의 port>`. 이 PC 안에서만 열린다. 외부 네트워크 요청은 없다.

- 넓은 화면에서는 왼쪽 사이드바(검색과 화면 목록)와 바탕을 같은 색으로 칠하고 본문만 둥근 판으로 띄운다. 사이드바 맨 위 버튼으로 접으면 아이콘 띠만 남고, 아이콘에 마우스를 올리면 이름표가 뜬다. 접은 띠의 돋보기를 누르면 사이드바가 펼쳐지며 검색칸에 커서가 간다. 접은 상태는 브라우저에 기억한다. 폭 760px 이하에서는 위쪽 막대를 쓴다.
- 문서가 바뀌면 화면이 바로 다시 그려지고, 새 문서와 새 줄이 잠깐 노랗게 칠해진다.
- "나" 화면 맨 위는 폴더 기록으로 계산한 사용 방법 레이더다: 공부 깊이(검증을 통과한 공부 노트), 공부 넓이(공부 노트 `tags`의 서로 다른 분야), 마무리(끝낸 질문과 끝낸 아이디어), 꾸준함(최근 14일 중 기록이 있는 날), AI 길들이기(최근 30일에 결정한 규칙과 사용자 정보 후보, 처리한 댓글). 축을 누르면 계산식, 목표치, 근거가 나온다. 옆에는 AI 코멘트(사용자 정보 자리의 `ai-comment.md`, 승인된 정보가 아닌 Claude의 의견)가 있고, 매일 9시 이후 첫 세션에서 훅이 갱신을 알린다. 칸 위에 마지막으로 고친 시각과 다음 갱신 시각이 보인다. 그 아래는 축마다 일주일 전과 비교한다. 더 아래에 Claude가 지금 쓰고 있는 나에 대한 정보를 근거와 함께 보여 준다: 사용자 정보(`profile.md`)의 승인된 항목, 기다리는 후보와 거절한 후보, 글쓰기 규칙. 틀린 항목은 "이건 아니에요"를 눌러 댓글을 남긴다. 모양 3 프로젝트에서는 이 화면이 홈 뷰어에 있고, 프로젝트 뷰어의 "나"에는 홈 뷰어로 가는 링크(꺼져 있으면 그 사실)를 보인다.
- 연결 그래프는 `related`와 백틱 경로로 문서를 잇는다. 기본으로 모든 연결 종류와 공통 문서(규칙, 목차, 장부, 기록), 보관 문서, 연결 없는 문서를 모두 그린다. 폴더는 그래프 왼쪽 아래 범례에서 눌러 숨기고, 나머지는 그래프 머리의 "필터" 버튼 안에서 끈다. 꺼 둔 것이 있으면 버튼에 개수가 뜬다. 보는 중에 문서가 생기거나 지워지면 새로 고침 없이 점과 선이 더해지고 빠진다. 문서는 폴더별로 모인다. 폴더마다 원 안에서 작은 원판(멀수록 약해지는 척력, 멀수록 세지는 중력, 허브 쪽이 약한 용수철, 충돌)을 이룬다. 폴더 안 연결이 많은 문서일수록 원 가운데에 놓이고, 원은 안의 점에 꼭 맞게 그려지며 서로 떨어져 있다. 원이나 폴더 이름을 끌면 폴더째 옮기고, 점을 밖으로 끌면 원이 늘었다가 놓으면 돌아온다. 폴더 이름은 선 위에 보인다. 문서 이름은 150% 이상 확대하거나 마우스를 올리면 보이고, 점끼리는 겹치지 않으며, "맞춤"은 보이는 것 전체가 들어오게 배율을 정한다. 선은 다른 점을 가로지르지 않고 매끄러운 활 하나로 휘어 피해 가며(선 길이의 22%까지, 넘으면 곧게), 배치할 때 선 가까이 있는 점은 밀려난다. 다른 폴더로 가는 선은 다발로 그린다: 출발 원 가장자리로 모여, 다른 폴더 원을 피하는 가장 짧은 길(격자 길 찾기 뒤 매끄럽게)을 함께 흐른 뒤, 도착 폴더 안에서 다른 문서를 피해 문서마다 갈라진다. 문서를 고르거나 마우스를 올리면 그 선도 같은 다발 길로 강조된다. 끄는 동안에는 피하기 계산을 건너뛰고 놓으면 다시 계산해서 끌기가 부드럽다. 실시간 갱신으로 새로 생긴 선은 그어지는 효과가 끝난 뒤 중간이 끊겨 보이지 않는다.
- 모양 3 프로젝트의 그래프는 폴더를 shared, private, 홈 세 영토로 묶는다. 홈은 이 프로젝트 문서가 가리키는 홈 노트만 그리고, 노트마다 프로젝트 문서 몇 개가 가리키는지(`← 4`)를 붙인다. 영토는 폴더 원들을 감싸는 옅은 색 면이고, 아이콘(열린 자물쇠, 자물쇠, 집)과 영어 이름이 붙는다. 이름에 마우스를 올리면 누가 보는 영역인지 뜬다. 영토끼리는 겹치지 않고, 다른 영토로 가는 선은 경계의 문에 모였다가 나란한 띠로 흐른다. 점은 자기 영토 밖으로 나가지 않고, 다른 폴더의 원과 이름 자리에 들어가지 않는다. 폴더 이름은 감싸는 것 없이 폴더 색 글자와 문서 수로 쓴다. 범례는 영토별로 묶이고 맨 위 단추로 접는다. "필터", "흔적", "맞춤"은 그래프 머리에 있고, 확대와 축소는 마우스 휠로 한다. "맞춤"은 범례와 옆 상자에 가리지 않는 자리에 그래프 전체가 들어오게 한다.
- 홈 뷰어의 그래프도 같은 영토로 그린다. 홈 폴더와 홈 맨 위 문서(원 없이 점으로)는 초록 홈 영토 하나에 모이고, 홈 노트가 가리키는 프로젝트마다 폴더 아이콘이 붙은 회색 영토가 하나씩 생긴다. 프로젝트 영토에는 가리킨 문서만 점으로 그리고, 이름은 확대하면 보인다. 범례에는 "projects" 아래 프로젝트마다 한 줄이 있다. 두 뷰어 모두 다른 작업 공간 영토(프로젝트의 홈, 홈의 프로젝트)의 제목을 누르면 그 뷰어의 그래프가 새 탭으로 열리고, 그 영토의 점을 누르면 그래프를 떠나지 않고 옆 패널에 문서가 뜬다(패널은 아래 항목).
- Claude가 답하는 동안 읽고 고친 문서가 연결 그래프에 순서대로 흔적으로 남는다. 이어서 거친 두 문서가 이미 연결돼 있으면 그 연결 선에 앞 문서에서 다음 문서 쪽으로 새 선처럼 색이 차오르고(읽음은 강조색, 고침은 바뀐 줄의 노란 색), 연결이 없는 두 문서는 선 없이 번호로만 순서를 보이고, 점마다 거쳐 간 차례 번호가 붙고(두 번 거치면 `2·6`), 가장 최근 점은 둘레가 퍼진다. 오른쪽 위 "흔적" 단추 바로 아래의 목록 상자가 3줄 높이로 순서를 보이며 가장 최근 줄로 스크롤한다. 오른쪽 문서 패널이 열리면 그 왼쪽으로 비키고, 아래나 전체 패널이 열려 있는 동안은 숨는다. Read, Edit, Write, MultiEdit, NotebookEdit와, 명령에 문서 경로가 그대로 든 Bash를 친다. Grep과 Glob은 치지 않는다. 서브에이전트가 읽은 점에 마우스를 올리면 "N번 · 서브에이전트가 읽음"이 뜬다. 새 메시지를 보내면 흔적이 비워지고, "맞춤" 옆 "흔적" 단추로 끈다. 같은 폴더에서 세션 여럿이 함께 돌면 가장 최근에 움직인 세션의 흔적을 보인다.
- 지난 메시지 뒤로 새로 생긴 문서와 연결은 다음 메시지를 보낼 때까지 연결 그래프에 남는다. 흔적(강조색, 노란 색)과 갈리게 뷰어의 추가 색을 쓴다. 새 선은 확대와 관계없이 굵게 은은히 번지고(새 선이 60개를 넘으면 번짐은 끈다), 흔적이 지나간 새 선은 흔적 색이 위에 보인다. 새 문서는 둘레가 칠해지고 점 오른쪽 아래에 "새" 꼬리표가 붙는다. 흔적 목록에도 새 문서 줄에 "새"가 붙고, 머리에 새 문서와 새 연결 수가 나온다. Claude가 만든 것뿐 아니라 그 사이 생긴 문서와 연결은 모두 친다. 필터를 바꿔 다시 보인 문서는 새 것으로 치지 않는다. 흔적 점과 새 문서의 이름은 다른 이름과 겹치지 않을 때만 보이고, 150%보다 작게 볼 때도 이 둘(과 고른 점)의 이름은 서로 겹치지 않으면 보인다. 메시지를 보낼 때 뷰어 서버가 꺼져 있었으면 서버가 켜진 뒤 처음 그린 모습부터 센다.
- 다른 작업 공간(`home:…`, `<이름>:…`)을 가리키는 연결은 가리킨 문서마다 흐린 "바깥 점"으로 그리고 작업 공간별로 묶는다. 빌드는 가리킨 문서만 읽어 제목과 본문을 싣고, 그 작업 공간의 다른 문서는 읽지 않는다. 점을 누르면 옆 패널에 문서가 뜨고, 패널의 단추로 그 뷰어를 새 탭으로 연다. 뷰어가 꺼져 있으면 알린다.
- 점(내 문서든 다른 작업 공간의 문서든)을 누르면 문서 화면과 같은 문서 뷰가 옆 패널에 열린다. 경로 줄, 속성 칩, 본문, 링크와 목차가 그대로 나온다. 링크와 목차는 문서 뷰가 900px 이상이면 오른쪽 열에 있고, 그보다 좁으면(옆 패널, 분할 화면의 문서 화면) 그 열이 본문 위 단추 줄(목차, 댓글, 연결, 피드백, 개수 표시)로 접힌다. 단추를 누르면 그 카드가 줄 아래 상자로 펼쳐지고, 단추 줄은 스크롤해도 위에 붙어 있으며, 본문에서 문장을 고르면 인용이 든 댓글 상자가 열린다. 목차 줄, 바깥 누르기, Esc로 다시 접히고(Esc는 상자만 닫고 패널은 그대로), 쓰던 댓글은 남는다. 내 문서는 패널에서 고치고 댓글도 남기고, 다른 작업 공간의 문서는 읽기만 한다. 패널이 열려 있는 동안 누른 점과 이웃 점이 강조로 남고, 패널에 가리지 않게 그래프가 움직인다. 패널 안의 링크는 패널에서 열린다. 머리줄의 X(또는 Esc)로 닫고, 단추는 내 문서면 "문서 화면으로", 다른 작업 공간이면 "<작업 공간> 뷰어에서 열기"다. 점을 두 번 누르면 지금처럼 문서 화면으로 간다. 그래프 옆에 360px 이상 남으면 패널이 오른쪽에 서고, 아니면 그래프 높이가 640px 이상일 때 아래쪽(높이의 58%)에, 그것도 아니면 그래프 전체를 덮는다. 그래서 화면 절반이나 2~4분할에서도 쓴다. 오른쪽 패널은 왼쪽 가장자리를 끌어 너비를 바꾸고(이 브라우저에 기억), 가장자리를 두 번 누르면 처음 너비로 돌아간다. 패널에서 고치거나 댓글을 남겨도 새로 고치지 않아 그래프 배치와 패널이 그대로이고, 쓰던 내용이 있는 채로 패널을 벗어나면 "쓰던 내용이 사라집니다. 계속할까요?"라고 묻는다. 쓰는 중에 들어온 파일 변경은 다 쓴 뒤에 반영한다. 흔적 상자("이번 답에서 거쳐 간 문서")는 오른쪽 위 "흔적" 단추 바로 아래에 있고, 오른쪽 패널이 열리면 그 왼쪽으로 비키며, 아래나 전체 패널이 열려 있는 동안은 숨는다.

훅은 `.siloroot/config.json`이 있는 폴더에서만 동작한다. 세션을 시작하면 뷰어 서버(모양 3 프로젝트면 홈 뷰어 서버도)를 켜고 브라우저로 프로젝트 뷰어를 연다(뷰어 화면이 이미 열려 있거나 대화 압축으로 다시 시작한 세션이면 열지 않는다). 그 폴더에 떠 있는 뷰어 서버가 설치된 플러그인보다 옛 버전이면 끄고 지금 버전으로 다시 켠다. 열려 있던 뷰어 화면은 다른 버전 서버에 다시 붙으면 스스로 새로 읽는다. 0.5.1 이하 서버가 준 화면은 그러지 못해서, Claude가 새로고침하라고 알린다. 메시지를 보낼 때 처리할 피드백이 있으면 알린다. 작업 공간이 설치된 플러그인보다 뒤처졌으면 세션을 시작할 때 업데이트를 알린다. 읽는 문서 흔적은 백그라운드 훅 둘(`"async": true`, Claude가 기다리지 않는다)이 도구를 쓸 때마다 문서 경로를 붙이고, 메시지를 보내면 그 세션 흔적을 비우고 새 메시지 시각을 `.siloroot/state/trail/turn.json`에 적는다. 뷰어 서버는 이 시각이 바뀌면 그때 문서와 연결 목록을 `.siloroot/state/turn-base.json`에 기준으로 남기고, 그 뒤 새로 생긴 것을 그래프에 표시한다. 흔적을 남기는 곳은 `.siloroot/state/trail/<세션>.jsonl`이고, 시각, 문서 경로, 읽음과 고침, 서브에이전트 id만 남긴다. 7일 넘게 쓰지 않은 다른 세션의 흔적 파일은 지운다. 0.1.x 방식(문서를 맨 위에 두는 방식) 폴더에 이미 `.gitignore`가 있었다면 `.siloroot/state/`를 직접 더한다.

모양 3 이상 프로젝트에서는 세션을 시작할 때 다른 훅 하나가 컨벤션(`shared/conventions/`) 본문을 Claude 맥락에 넣는다. 읽으라고 시키지 않아도 Claude가 컨벤션을 따른다. `/clear`와 대화 압축 뒤에도 다시 넣는다. 문서마다 경로를 붙이고 속성은 뗀다. 폴더 안내(`README.md`)와 `status`가 `폐기`, `바뀜`인 문서는 넣지 않는다. Claude Code는 훅 출력 하나를 10,000자로 제한하고 넘으면 앞부분만 보이므로, 9,000자를 넘으면 본문 대신 문서 목록과 경로를 넣고 모두 읽고 시작하라고 쓴다. 홈에는 컨벤션 자리가 없어 넣지 않는다.

## 사용 기록

SiloRoot가 어디서 느리고 토큰을 많이 쓰는지 보려고, 플러그인이 단계마다 JSON 한 줄을 `.siloroot/state/metrics.jsonl`에 남긴다. 기본으로 켜져 있고, 이 PC에만 남으며, `state/`의 다른 파일처럼 git에서 빠진다.

| 단계 | 재는 것 |
| --- | --- |
| `turn:siloroot:<스킬>` | SiloRoot 스킬을 쓴 턴(메시지 하나와 그 응답 전체). 슬래시 명령으로 불렀든 Claude가 불렀든 같다 |
| `turn:siloroot-docs` | SiloRoot 스킬 없이 작업 공간이나 홈의 문서를 읽거나 고친 턴(상태 폴더와 설정 파일은 빼고, 문서 폴더를 다룬 명령은 넣는다). 그 세션에서 앞서 SiloRoot 스킬을 썼으면 요약에서 `turn:siloroot-docs (siloroot:<스킬> 뒤)`로 따로 묶어서, `note`나 `verify`의 이어지는 문답 턴을 볼 수 있다 |
| `turn:other` | 작업 공간의 나머지 턴. 비교 기준이다 |
| `hook:autostart`, `hook:notify-session`, `hook:notify-prompt`, `hook:conventions`, `hook:metrics-turn` | 훅 실행 시간(Node가 뜨는 시간 포함). 알림 훅과 컨벤션 훅은 Claude에게 덧붙인 글자 수도 남긴다 |
| `script:init`, `script:update`, `script:build` (`:data-only`, `:seen`, `:seen-path`) | 스크립트 실행 시간과 문서 수 |
| `context:always-loaded` | 세션을 시작할 때 잰, 매 턴 불러오는 `.siloroot/CLAUDE.md`와 `profile.md`의 글자 수 |

- 턴 기록은 `Stop` 훅이 남긴다. 훅 입력의 대화 기록(`transcript_path`)을 지난번 읽은 곳부터 읽고, 응답마다 있는 `usage`(입력, 출력, 캐시 읽기, 캐시 쓰기 토큰)를 더한다. 여러 줄로 나뉜 응답은 메시지 id로 한 번만 센다. 서브에이전트 토큰(`<세션>/subagents/`)은 `sub` 칸에 따로 둔다. 도구 결과가 맥락에 들여온 글자 수(`resultChars`, 도구 이름별)와 그 가운데 문서를 다룬 호출의 몫(`docChars`)도 남겨서, 문서를 찾아보는 데 드는 비용을 볼 수 있다. 턴마다 자리 이름별로 참고로 읽은 문서 수(`docReads`, 같은 턴에 고친 문서는 뺌)와 고친 문서 수(`docEdits`), 문서 밖 파일을 고친 수(`codeEdits`), 문서 경로 없이 문서 폴더를 다룬 명령 수(`docScripts`)도 남긴다. 문서인지, 읽었는지 고쳤는지는 연결 그래프의 흔적과 같은 기준으로 가른다. 내용은 꺼내지 않고 길이만 센다. 읽은 위치는 세션마다 `.siloroot/state/metrics-cursor/`에 따로 두어 함께 도는 세션이 서로 덮지 않는다. 위치를 잃어 같은 턴이 두 번 남아도 요약은 한 번만 센다.
- 기록에는 단계 이름, 시각, 걸린 시간, 토큰 수, 도구 이름별 횟수와 시간, SiloRoot 스킬 이름, 세션 id, 자리 이름(`decisions`, `worklog`처럼 SiloRoot가 정한 이름뿐)별 문서 수만 들어간다. 문서 내용, 프롬프트, 파일 경로, 다른 플러그인의 스킬 이름은 남기지 않는다.
- 기록이 실패해도 원래 작업은 그대로 간다. `Stop` 훅은 늘 출력 없이 0으로 끝난다.
- 끄려면 `.siloroot/config.json`에 `"metrics": false`를 넣거나 환경 변수 `SILOROOT_METRICS=0`을 준다. 파일이 5 MB를 넘으면 `metrics.1.jsonl`로 옮기고 새로 쌓는다.

요약은 프로젝트 폴더에서 플러그인 폴더(마켓플레이스로 설치했으면 `~/.claude/plugins/cache/<마켓플레이스>/siloroot/<버전>/`)의 스크립트로 본다. `--days 7`은 최근 일주일만, `--json`은 모은 값을 JSON으로 낸다.

```powershell
node "<플러그인 폴더>/scripts/metrics.mjs" . --days 7
```

시간, 토큰, 비용을 가장 많이 쓴 단계를 먼저 보여 주고, 턴 표(비용 순), 턴 나눔 표, 자리별 문서 수, 스크립트·훅 표를 낸다.

- 턴 나눔은 턴을 활용(참고 문서를 읽고 코드를 고침), 코드만, 문서 일(참고 문서를 읽고 코드는 안 고침), 기록만(참고 문서 없이 문서만 고침), 스크립트로 문서를 다룸, 안 건드림으로 나눈다. 참고 문서는 작업 일지, 폴더 안내, 규칙 문서, 글쓰기 규칙을 뺀 문서다. 기록이 일에 쓰이는지 보려는 표다. 이 칸이 없는 옛 기록은 빼고 센다.
- 스크립트나 PowerShell 안에서 읽고 고친 문서는 문서별로 가르지 못한다.

- 비용은 응답마다 API 정가로 환산한 값이다(`lib/pricing.mjs`, 2026-11-03 기준 값). 서브에이전트를 포함하고, 1시간 캐시 쓰기와 fast 모드는 그 값으로 센다. 단계끼리 견주는 상대값이고 구독 요금제의 실제 청구와는 다르다. 표에 없는 모델의 응답은 값을 매기지 않고 따로 센다.
- 캐시 읽기 몫은 그 비용 가운데 대화를 캐시에서 다시 읽는 데 든 비율이다. 도구를 한 번 부를 때마다 새 요청이 가서 대화 전체를 다시 읽으므로, 이 몫이 크면 호출 횟수를 줄이는 것이 가장 남는다.
- 작업 토큰은 입력 + 출력 + 캐시 쓰기이고 서브에이전트를 포함한다. 캐시 읽기 토큰은 대화가 길수록 커지므로 칸을 따로 두고, 값은 위 비용에 들어간다.
- 턴은 통째로 한 단계에 들어간다. `/siloroot:note`를 쓰면서 다른 일도 한 메시지는 모두 `turn:siloroot:note`로 세므로, 스킬별 숫자는 어림값이다.
- 결과 글자는 토큰이 아니라 글자 수다. 한글은 한 글자가 대략 한 토큰 이상이다.
- 턴 시간에는 사용자를 기다린 시간도 들어간다. 질문에 답하거나 권한을 승인하는 동안은 도구 시간(`AskUserQuestion`, `Edit`, `Write` 등)으로 잡힌다.
- 턴이 끝난 뒤에도 돌아가는 배경 서브에이전트의 토큰은 세지 않는다.

## 개발

```powershell
npm test
claude plugin validate .
```

버전은 PR마다 올리지 않고 내보낼 때 올린다. 기능은 `main`에 쌓았다가 부 버전(0.x.0) 하나로 함께 내보내고, 이미 내보낸 버전의 버그 수정은 바로 패치 버전(0.x.y)으로 낸다. 내보내기 전의 `main`을 써 보려면 내려받은 저장소를 터미널 세션 하나에 불러온다.

```powershell
claude --plugin-dir <내려받은 경로>
```

그 세션에만 적용된다. 그동안 이 프로젝트에 설치된 SiloRoot는 꺼 두어 훅이 같이 돌지 않게 하고(`claude plugin disable siloroot@siloroot --scope project`), 끝나면 다시 켠다(`claude plugin enable siloroot@siloroot --scope project`).

개인 정보 검사 테스트는 git에 올리지 않는 `test/banned-words.local.txt`(한 줄에 낱말 하나)에서 금지어를 읽는다. 파일이 없으면 금지어 없이 지나간다.

README는 영어(`README.md`)와 한국어(`README.ko.md`) 두 벌이다. 한쪽을 고치면 다른 쪽도 같이 고친다.
