# SiloRoot

[English](README.md) | **한국어**

도구마다 흩어진 기록(사일로)을 마크다운 폴더 하나(뿌리)로 모으는 Claude Code 플러그인이다. 폴더의 마크다운 파일이 원본이고, 사람은 로컬 뷰어 화면으로, AI는 파일로 같은 내용을 본다. 아직 초기 버전(v0)이다.

## 준비물

- Claude Code
- `PATH`에 잡힌 Node.js (훅과 뷰어가 `node`로 실행된다)

## 설치

```powershell
claude plugin marketplace add Q07K/siloroot
cd <작업 공간으로 쓸 폴더>
claude plugin install siloroot@siloroot --scope project
```

저장소를 내려받아 쓰려면 첫 줄 대신 `claude plugin marketplace add <내려받은 경로>`를 쓴다.

그 폴더에서 Claude Code를 열고 `/siloroot:init`을 실행한다.

### Claude에게 맡기기

명령을 직접 치지 않고 Claude Code에 말로 맡겨도 된다. 데스크톱 앱처럼 터미널을 따로 열지 않고 쓰는 곳에서 편하다. 작업 공간으로 쓸 폴더를 Claude Code에서 프로젝트로 열고 이렇게 말한다.

```text
이 프로젝트에 SiloRoot 플러그인을 설치해 줘. 마켓플레이스는 Q07K/siloroot야.
```

- Claude가 지금 열린 프로젝트 폴더에서 위의 두 명령을 실행한다. 폴더 경로를 말하거나 `cd`할 필요는 없다. 권한 설정에 따라 실행 승인을 한 번 눌러야 할 수 있다.
- 설치를 부탁한 대화에는 적용되지 않는다. 설치가 끝나면 같은 프로젝트에서 새 세션을 열고 `/siloroot:init`을 실행한다.
- 업데이트도 같다. "이 프로젝트의 SiloRoot 플러그인 업데이트해 줘"라고 하면 Claude가 `claude plugin update siloroot@siloroot --scope project`를 실행한다. 적용하려면 새 세션을 연다.

## 스킬

| 스킬 | 언제 |
| --- | --- |
| `/siloroot:init` | 폴더를 작업 공간으로 만든다. 없는 파일만 만들고 뷰어를 연다 |
| `/siloroot:note` | 기술 개념을 문답으로 공부한다. 공부 노트가 생기고 이어 적힌다. 질문이 옆 주제로 번지면 노트를 나누고 링크로 묶는다 |
| `/siloroot:verify` | "검증해 줘". Claude가 질문하고 판정해 검증 기록과 이해도를 갱신한다 |
| `/siloroot:feedback` | 뷰어에서 남긴 댓글과 웹 편집을 처리하고, Claude가 일하면서 본 작업 습관과 선호를 사용자 정보 후보로 남긴다. "앞으로 항상 …해 줘"라고 직접 말한 것도 후보를 먼저 만들고, 그 말을 승인으로 보아 `05-profile/profile.md`에 넣는다. 훅이 알려 준다 |

한 대화가 공부, 아이디어, 결정, 프로젝트 사이를 오가도 된다. 대화는 흐르게 두고, Claude가 내용의 종류를 보고 알맞은 폴더에 문서를 나눠 서로 잇는다. 규칙은 작업 공간의 `CLAUDE.md` 블록에 들어간다.

## 만들어지는 폴더

SiloRoot가 만드는 문서는 모두 프로젝트의 `.siloroot/` 폴더 안에 들어간다. 사람은 뷰어 화면으로 보고 문서는 Claude가 관리하니, 코드 옆에 섞이지 않게 한 단계 감싼다. 팀이 같이 쓰는 `CLAUDE.md`와 `.gitignore`는 고치지 않는다.

| 경로 | 내용 |
| --- | --- |
| `.siloroot/CLAUDE.md` | SiloRoot 표시 블록(폴더 지도와 규칙). 블록 밖은 자유 |
| `.siloroot/metadata-guide.md`, `writing-guide.md` | 문서 속성 약속, 글쓰기 규칙 |
| `.siloroot/01-log/` | 작업 기록, 미해결 질문 |
| `.siloroot/02-study/` | 공부 노트와 주제 목록(이해도) |
| `.siloroot/03-ideas/` | 아이디어와 만들기 시작한 프로젝트, 그 결정 기록 |
| `.siloroot/04-feedback/` | 뷰어 댓글, 글쓰기 규칙 후보, 사용자 정보 후보 |
| `.siloroot/05-profile/` | 승인한 작업 습관과 선호(`profile.md`). 규칙 블록이 불러와서 모든 대화에 쓰인다 |
| `.siloroot/config.json`, `state/` | 설정(포트, 폴더 이름, 배치)과 뷰어 생성물 |
| `CLAUDE.local.md` | `@.siloroot/CLAUDE.md` 한 줄로 SiloRoot 규칙을 불러온다. 이미 있으면 표시 블록만 끝에 붙인다 |
| `.ignore` | git은 `.siloroot/`를 무시해도 Claude의 검색(ripgrep)은 찾게 한다(`!.siloroot/`). 생성물은 검색에서도 뺀다 |
| git 제외 목록(`.git/info/exclude`) | `.siloroot/`, `.ignore`, `CLAUDE.local.md`를 이 PC의 이 저장소에서만 커밋 대상에서 뺀다. git 저장소일 때만 쓴다 |

- 문서 안의 경로(`related`, 백틱 경로)는 `.siloroot/` 기준이다. Claude는 파일을 열거나 검색할 때만 앞에 `.siloroot/`를 붙인다.
- `.git/info/exclude`는 PC마다 따로라서, 같은 프로젝트를 다른 PC에서 받으면 init을 한 번 더 실행한다.
- 0.1.x에서 문서를 프로젝트 맨 위에 바로 두는 방식으로 초기화한 폴더는 그 방식 그대로 동작한다. 다시 init을 실행해도 옮기지 않는다.

템플릿과 스킬 문구는 지금 한국어로만 되어 있다.

## 뷰어

`http://127.0.0.1:<config.json의 port>`. 이 PC 안에서만 열린다. 외부 네트워크 요청은 없다.

- 넓은 화면에서는 왼쪽 사이드바(검색과 화면 목록)와 바탕을 같은 색으로 칠하고 본문만 둥근 판으로 띄운다. 사이드바 맨 위 버튼으로 접으면 아이콘 띠만 남고, 아이콘에 마우스를 올리면 이름표가 뜬다. 접은 띠의 돋보기를 누르면 사이드바가 펼쳐지며 검색칸에 커서가 간다. 접은 상태는 브라우저에 기억한다. 폭 760px 이하에서는 위쪽 막대를 쓴다.
- 문서가 바뀌면 화면이 바로 다시 그려지고, 새 문서와 새 줄이 잠깐 노랗게 칠해진다.
- "나" 화면 맨 위는 폴더 기록으로 계산한 사용 방법 레이더다: 공부 깊이(검증을 통과한 공부 노트), 공부 넓이(공부 노트 `tags`의 서로 다른 분야), 마무리(끝낸 질문과 끝낸 아이디어), 꾸준함(최근 14일 중 기록이 있는 날), AI 길들이기(최근 30일에 결정한 규칙과 사용자 정보 후보, 처리한 댓글). 축을 누르면 계산식, 목표치, 근거가 나온다. 옆에는 AI 코멘트(`05-profile/ai-comment.md`, 승인된 정보가 아닌 Claude의 의견)가 있고, 매일 9시 이후 첫 세션에서 훅이 갱신을 알린다. 칸 위에 마지막으로 고친 시각과 다음 갱신 시각이 보인다. 그 아래는 축마다 일주일 전과 비교한다. 더 아래에 Claude가 지금 쓰고 있는 나에 대한 정보를 근거와 함께 보여 준다: `05-profile/profile.md`의 승인된 항목, 기다리는 후보와 거절한 후보, 글쓰기 규칙. 틀린 항목은 "이건 아니에요"를 눌러 댓글을 남긴다.
- 연결 그래프는 `related`와 백틱 경로로 문서를 잇는다. 기본으로 모든 연결 종류와 공통 문서(규칙, 목차, 장부, 기록), 보관 문서, 연결 없는 문서를 모두 그린다. 폴더는 그래프 왼쪽 아래 범례에서 눌러 숨기고, 나머지는 오른쪽 위 "필터" 버튼 안에서 끈다. 꺼 둔 것이 있으면 버튼에 개수가 뜬다. 보는 중에 문서가 생기거나 지워지면 새로 고침 없이 점과 선이 더해지고 빠진다. 문서는 폴더별로 모인다. 폴더마다 원 안에서 작은 원판(멀수록 약해지는 척력, 멀수록 세지는 중력, 허브 쪽이 약한 용수철, 충돌)을 이룬다. 폴더 안 연결이 많은 문서일수록 원 가운데에 놓이고, 원은 안의 점에 꼭 맞게 그려지며 서로 떨어져 있다. 원이나 폴더 이름을 끌면 폴더째 옮기고, 점을 밖으로 끌면 원이 늘었다가 놓으면 돌아온다. 폴더 이름은 선 위에 보인다. 문서 이름은 150% 이상 확대하거나 마우스를 올리면 보이고, 점끼리는 겹치지 않으며, "맞춤"은 보이는 것 전체가 들어오게 배율을 정한다. 선은 다른 점을 가로지르지 않고 매끄러운 활 하나로 휘어 피해 가며(선 길이의 22%까지, 넘으면 곧게), 배치할 때 선 가까이 있는 점은 밀려난다. 다른 폴더로 가는 선은 다발로 그린다: 출발 원 가장자리로 모여, 다른 폴더 원을 피하는 가장 짧은 길(격자 길 찾기 뒤 매끄럽게)을 함께 흐른 뒤, 도착 폴더 안에서 다른 문서를 피해 문서마다 갈라진다. 문서를 고르거나 마우스를 올리면 그 선도 같은 다발 길로 강조된다. 끄는 동안에는 피하기 계산을 건너뛰고 놓으면 다시 계산해서 끌기가 부드럽다. 실시간 갱신으로 새로 생긴 선은 그어지는 효과가 끝난 뒤 중간이 끊겨 보이지 않는다.

훅은 `.siloroot/config.json`이 있는 폴더에서만 동작한다. 세션을 시작하면 뷰어 서버를 켜고 브라우저로 뷰어를 연다(뷰어 화면이 이미 열려 있거나 대화 압축으로 다시 시작한 세션이면 열지 않는다). 메시지를 보낼 때 처리할 피드백이 있으면 알린다. 0.1.x 방식(문서를 맨 위에 두는 방식) 폴더에 이미 `.gitignore`가 있었다면 `.siloroot/state/`를 직접 더한다.

## 사용 기록

SiloRoot가 어디서 느리고 토큰을 많이 쓰는지 보려고, 플러그인이 단계마다 JSON 한 줄을 `.siloroot/state/metrics.jsonl`에 남긴다. 기본으로 켜져 있고, 이 PC에만 남으며, `state/`의 다른 파일처럼 git에서 빠진다.

| 단계 | 재는 것 |
| --- | --- |
| `turn:siloroot:<스킬>` | SiloRoot 스킬을 쓴 턴(메시지 하나와 그 응답 전체). 슬래시 명령으로 불렀든 Claude가 불렀든 같다 |
| `turn:siloroot-docs` | SiloRoot 스킬 없이 `.siloroot/` 안 파일을 읽거나 고친 턴 |
| `turn:other` | 작업 공간의 나머지 턴. 비교 기준이다 |
| `hook:autostart`, `hook:notify-session`, `hook:notify-prompt`, `hook:metrics-turn` | 훅 실행 시간. 알림 훅은 Claude에게 덧붙인 글자 수도 남긴다 |
| `script:init`, `script:build` (`:data-only`, `:seen`, `:seen-path`) | 스크립트 실행 시간과 문서 수 |
| `context:always-loaded` | 세션을 시작할 때 잰, 매 턴 불러오는 `.siloroot/CLAUDE.md`와 `profile.md`의 글자 수 |

- 턴 기록은 `Stop` 훅이 남긴다. 훅 입력의 대화 기록(`transcript_path`)을 지난번 읽은 곳부터 읽고, 응답마다 있는 `usage`(입력, 출력, 캐시 읽기, 캐시 쓰기 토큰)를 더한다. 여러 줄로 나뉜 응답은 메시지 id로 한 번만 센다. 서브에이전트 토큰(`<세션>/subagents/`)은 `sub` 칸에 따로 둔다.
- 기록에는 단계 이름, 시각, 걸린 시간, 토큰 수, 도구 이름별 횟수와 시간, SiloRoot 스킬 이름, 세션 id만 들어간다. 문서 내용, 프롬프트, 파일 경로, 다른 플러그인의 스킬 이름은 남기지 않는다.
- 기록이 실패해도 원래 작업은 그대로 간다. `Stop` 훅은 늘 출력 없이 0으로 끝난다.
- 끄려면 `.siloroot/config.json`에 `"metrics": false`를 넣거나 환경 변수 `SILOROOT_METRICS=0`을 준다. 파일이 5 MB를 넘으면 `metrics.1.jsonl`로 옮기고 새로 쌓는다.

요약은 프로젝트 폴더에서 플러그인 폴더(마켓플레이스로 설치했으면 `~/.claude/plugins/cache/<마켓플레이스>/siloroot/<버전>/`)의 스크립트로 본다. `--days 7`은 최근 일주일만, `--json`은 모은 값을 JSON으로 낸다.

```powershell
node "<플러그인 폴더>/scripts/metrics.mjs" . --days 7
```

시간을 가장 많이 쓴 단계와 토큰을 가장 많이 쓴 단계를 먼저 보여 주고, 턴 표와 스크립트·훅 표를 낸다.

- 작업 토큰은 입력 + 출력 + 캐시 쓰기이고 서브에이전트를 포함한다. 캐시 읽기는 대화가 길수록 커져서 어느 단계가 비싼지 가리므로 따로 둔다.
- 턴은 통째로 한 단계에 들어간다. `/siloroot:note`를 쓰면서 다른 일도 한 메시지는 모두 `turn:siloroot:note`로 세므로, 스킬별 숫자는 어림값이다.
- 턴 시간에는 사용자를 기다린 시간도 들어간다. 질문에 답하거나 권한을 승인하는 동안은 도구 시간(`AskUserQuestion`, `Edit`, `Write` 등)으로 잡힌다.
- 턴이 끝난 뒤에도 돌아가는 배경 서브에이전트의 토큰은 세지 않는다.

```powershell
npm test
claude plugin validate .
```
