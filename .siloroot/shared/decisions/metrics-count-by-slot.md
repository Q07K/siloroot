# 사용 기록은 턴마다 문서 읽기·쓰기를 자리별 횟수로 센다

## 맥락

- 외부 제품 피드백이 "기록은 잘하지만 일에 쓰이는지 모른다"를 이탈 원인 가설로 냄
- 사용 기록을 처음 뽑아 보니 문서 턴이 85% 안팎이었지만, 작업 일지 쓰기 때문이 많고 읽기·쓰기를 가르지 않아 활용인지 기록인지 알 수 없었음
- 문서 턴을 가르는 기준도 어긋나 있었음(`shared/issues/metrics-doc-detection.md`)

## 정한 것 (사용자, 2026-11-26)

- 안 B로 함: 턴마다 읽은 문서 수, 고친 문서 수를 자리 이름별로 셈
- 문서가 아닌 파일(코드 등)을 고친 수도 셈
- 문서 경로는 남기지 않음. 자리 이름은 SiloRoot가 정한 폴더 이름이라 남겨도 됨

## AI가 정한 세부 (바꿀 수 있음)

- 문서 가르기와 읽기·쓰기 가르기는 흔적의 구현(`lib/trail.mjs`의 `toDocPath`, `entriesFromHook`)을 그대로 씀. 새로 만들지 않음
- 자리 이름은 관리 블록 자리 표의 이름을 씀. 홈 문서는 홈 자리 이름 앞에 `home:`을 붙임. 사용자가 더한 폴더는 "기타"로 묶음
- 같은 턴에서 같은 문서를 여러 번 읽으면 한 번으로 셈

## 버린 것

| 안 | 버린 까닭 |
| --- | --- |
| A. 횟수만 | 작업 일지만 쓴 턴과 결정을 읽고 일한 턴을 가를 수 없음 |
| C. 흔적 쌓기 | 문서 경로가 남음. 근거 보이기(`shared/ideas/reuse-evidence.md`)를 만들 때 함께 봄 |

## 근거

- 이 작업 공간 사용 기록(2026-11-23 ~ 11-26, 369턴): 문서를 건드린 턴 비율 83~86%(11-24 ~ 11-26), 읽기·쓰기 구분 없음
- 흔적은 이미 읽음·고침을 가르고 홈 문서도 잡음. 사용 기록과 기준이 다름

## 미리 뽑아 본 값 (2026-11-26)

- 코드를 고치기 전에, 지난 대화 기록에 B안 셈을 한 번 돌림
  - 자료: 이 저장소의 대화 기록 28세션(11-23 ~ 11-26), 도구를 쓴 턴 440개
  - 흔적의 가르기(`entriesFromHook`, `toDocPath`)를 그대로 씀. 옛 모양 폴더 이름(`03-ideas`, `01-log` 등)은 지금 자리 이름으로 묶음
  - 참고 읽기: 작업 일지, README, 규칙 문서를 빼고, 같은 턴에 고친 문서도 뺌(Edit 도구는 고치기 전에 읽기를 요구함)

### 보인 것 (AI)

- B로 가른 숫자는 85% 한 덩어리보다 훨씬 많은 것을 말함. 만들 값어치가 있음
- 코드를 고친 세션의 절반은 고치기 전에 참고 문서를 하나도 읽지 않음. 관리 블록의 "코드 열기 전에 로드맵과 결정 먼저 보기"가 반만 지켜짐
- 결정은 쓴 것(25)보다 읽힌 것(14)이 적음. 코드 수정 전에 결정을 읽은 세션은 1개
- 아이디어·논의·작업 일지는 쓰기가 읽기의 3~6배
- 11-26은 기록만 턴이 줄고 문서 일·활용 턴이 늘었음. 다만 하루 차이라 추세로 보기는 이름

### 이 값의 한계

- 서브에이전트, 다른 폴더(worktree) 세션은 빠짐
- Grep·Glob으로 찾은 것, 스크립트·PowerShell로 다룬 문서는 빠짐
- 읽은 문서를 판단에 썼는지는 모름
- 대화가 압축되기 전 앞부분에서 읽은 것은 세션 단위에서만 잡힘
