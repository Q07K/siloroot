# 로드맵과 구현 계획을 가른다

## 맥락

`shared/roadmap/`의 문서 세 개(280~425줄)는 모두 기능 하나의 구현 계획이었다. 에이전트가 따라가는 체크 목록이 통째로 들어 있다. 프로젝트 전체에서 무엇을 어떤 순서로 만드는지 보여 주는 로드맵은 하나도 없었다.

## 정한 것 (사용자, 2026-11-25)

- 로드맵: 프로젝트에 한 장. 무엇을 어떤 순서로 만드는지, 지금 어디까지 왔는지. 늘 지금 상태로 고친다.
- 구현 계획: 기능마다 하나. 다 만들면 끝나는 문서다.

## 자리 (사용자, 2026-11-25)

- 로드맵은 `shared/roadmap.md` 파일 하나. 한 장뿐이라 폴더를 두면 노드 하나짜리 클러스터가 된다.
- 구현 계획은 `shared/plans/`, 기능 하나에 하나.

## 로드맵에 올리는 것 (사용자, 2026-11-25)

사용자가 물었다: 고민하고 공부하다 "오, 이거 당장 말고 나중에 하자"고 하면 로드맵에 올라가야 하나.

- 로드맵에는 만들기로 정한 것만 올린다. 기준은 "언제"가 아니라 "만들기로 정했나"다.
- 칸은 셋: 지금(진행 중), 다음(곧 시작), 나중(만들기로 했지만 때는 정하지 않음).

| 대화에서 | 로드맵 | 아이디어 문서 `status` |
| --- | --- | --- |
| "지금 만들자" | 지금 칸, 요구사항 문서를 만든다 | `진행 중` |
| "다음에 바로 하자" | 다음 칸 | `아이디어` |
| "하자, 근데 나중에" | 나중 칸에서 아이디어를 가리킨다 | `보류` |
| "생각해 보자", 공부 중 | 올리지 않는다 | `아이디어`(또는 홈 공부 노트) |

## 따라오는 일

- 이 작업 공간의 세 계획 문서를 `shared/plans/`로 옮기고, `shared/roadmap.md`를 새로 쓴다.

## 반영

- 플러그인: 플러그인 PR #30(2026-11-25 머지, 0.8.0으로 내보냄). 자리표, 템플릿(`shared/roadmap.md`), 마이그레이션 003(`shared/roadmap/` → `shared/plans/`)
- 이 작업 공간: 계획 3개를 `shared/plans/`로 옮겼고 `shared/roadmap.md`를 썼다(2026-11-25)
