# 부 버전은 작업 공간 모양이 바뀔 때만 올린다

## 맥락

연결 그래프 개편은 원래 0.8에 넣으려던 것인데, 0.8.0을 먼저 내보내는 바람에 빠졌다. 그때 규칙은 내보낼 때마다 부 버전(0.x.0)을 올리는 것이었다. 그대로 따르면 0.9.0이 되고, 사용자는 "버전업이 너무 빠르다"고 했다. 반대로 0.8.1로 내면 패치 버전은 버그 수정용이라는 규칙과 어긋났다.

## 정한 것 (사용자, 2026-11-25)

| 바뀌는 것 | 올리는 자리 |
| --- | --- |
| 작업 공간 모양(`SCHEMA`), 마이그레이션 있음 | 부 버전(0.x.0) |
| 새 기능, 화면 개편, 템플릿과 관리 블록, 버그 수정 | 패치 버전(0.x.y) |

- 내보내는 때는 그대로다. 묶음마다 한 번 내보내고, 내보낼지는 사용자가 정한다.
- 연결 그래프 개편은 이 규칙으로 0.8.1이다.

## 버린 것

- 내보낼 때마다 부 버전을 올리기(이전 규칙): 기능 묶음 하나가 0.1씩이라 번호가 빨리 오른다.
- 이번 한 번만 0.8.1로 내고 규칙은 두기: 다음 묶음에서 같은 고민이 반복된다.

## 근거

- 1.0 전 시맨틱 버저닝에서는 부 버전을 깨지는 변경에 쓴다. 이 플러그인에서 깨지는 변경은 `/siloroot:update`가 폴더와 문서를 옮겨야 하는 모양 변경이다.
- 이렇게 하면 번호만 보고도 업데이트에서 파일이 옮겨지는지 안다. 부 버전이면 옮겨지고, 패치면 관리 블록만 맞춘다.
