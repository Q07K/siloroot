# 요구사항은 기능마다 한 문서, 그 기능의 중심

## 맥락

아이디어는 대화에서 흩어져 나오고 버려지기도 한다. 남는 것은 "어떤 문제를 왜, 어떻게 풀었나"다. 사용자는 이것이 잘 남아야 나중에 포트폴리오로 정리하기도 좋다고 했다. 지금은 아이디어 문서가 요구사항 일을 일부 맡고, 만들기 시작할 때 요구사항으로 굳히는 단계가 없다.

## 정한 것 (사용자, 2026-11-25)

- `shared/requirements/`에 기능 하나에 문서 하나를 둔다.
- 아이디어를 만들기 시작할 때(`진행 중`) 만든다.
- 절: 문제(누가 무엇 때문에), 목표와 비목표(성공 기준), 거쳐 온 길(이 기능을 낳은 아이디어, 결정 기록, 설계, 구현 계획, 이슈의 경로만), 결과(무엇이 바뀌었나, 숫자).
- 세부는 각 자리 문서에 두고 여기서는 가리키기만 한다.

## 버린 것

- 아이디어 문서에 절로 더하기: 아이디어는 여러 개가 한 기능으로 모이기도 하고, 아이디어 문서는 흩어진 생각을 담는 곳이라 결과를 모으는 중심이 되기 어렵다.

## 반영

- 플러그인: 플러그인 PR #30(2026-11-25 머지, 0.8.0으로 내보냄). 요구사항 자리와 README 틀
- 이 작업 공간: 로드맵 "지금" 칸의 두 기능에 요구사항 문서를 썼다(2026-11-25)
