# 읽는 문서 흔적 설계

`shared/ideas/live-reading-graph.md`의 시안(`shared/ideas/live-reading-graph-mockup.gif`)을 사용자가 2026-11-24 "이대로 만들기"로 승인한 뒤 쓴 설계다. 논의 과정은 private/discussions/2026-11-24-live-reading-graph.md에 있다. "AI가 정함"이라고 적은 것은 사용자가 따로 정하지 않아 AI가 고른 것이다.

## 1. 왜

사용자는 작업하는 동안 뷰어의 연결 화면을 열어 둔다. Claude가 한 번 답하면서 어떤 문서를 어떤 순서로 거쳐 갔는지 그래프에서 보고 싶어 한다.

## 2. 목표와 하지 않을 것

**목표**
- Claude가 문서를 읽거나 고칠 때마다 연결 그래프에 흔적이 순서대로 쌓인다.
- 사용자가 새 메시지를 보내면 흔적이 비워진다(사용자).
- Claude의 도구 호출이 느려지지 않는다(사용자).

**하지 않을 것**
- 지난 답의 흔적을 모아 보는 기록 화면. 흔적은 한 번의 답까지만 남는다.
- Grep, Glob으로 훑은 파일. 읽은 것이 아니라 찾은 것이다(AI가 정함).
- `.siloroot` 밖의 코드 파일. 그래프에 없는 파일이다.

**실패로 보는 것**
- Claude가 도구를 쓸 때 기다리게 되는 것.
- 흔적 목록이 알림 상자나 정보 상자, 폴더 원을 가려서 그래프를 못 보게 되는 것.
- 뷰어에 없던 새 모양(화살표, 새 색, 새 상자 모양)이 생기는 것. 시안처럼 뷰어에 있는 모양만 쓴다(사용자 지적).

## 3. 비교한 방법

| 방법 | 장단점 | 결과 |
| --- | --- | --- |
| A. `PostToolUse` 훅을 백그라운드(`"async": true`)로 | 공식 방식, Claude가 기다리지 않음, 서브에이전트도 잡힘. 호출마다 뒤에서 node가 한 번 뜸 | **사용자가 고름** |
| B. 뷰어 서버가 대화 기록(JSONL)을 따라 읽기 | 호출마다 붙는 것이 없음. Claude Code 내부 형식이라 바뀌면 깨짐, 서브에이전트 기록은 다른 파일 | 고르지 않음 |
| C. 기다리는 훅 | 호출마다 수십 ms 늦어짐 | 뺌 |
| `http` 훅 | node를 안 띄움. 뷰어 포트가 프로젝트마다 달라(4180~4299) 플러그인 훅 설정에 주소를 고정할 수 없음 | 못 씀 |

## 4. 정한 것

### 4.1 기록 (훅)

- `hooks/hooks.json`에 `PostToolUse` 훅을 더한다. matcher는 `Read|Edit|Write|MultiEdit|NotebookEdit|Bash`, `"async": true`. 실행은 새 스크립트 `scripts/trail.mjs`.
- `.siloroot/config.json`이 없는 폴더에서는 아무것도 하지 않는다(다른 훅과 같다). 무엇이 실패해도 출력 없이 0으로 끝난다.
- 무엇을 칠지(AI가 정함):
  - Read는 `read`(읽음). Edit, Write, MultiEdit, NotebookEdit는 `edit`(고침).
  - Bash는 명령 문자열에 문서 경로가 그대로 들어 있을 때만 `read`로 친다. Claude가 `cat`, `sed`로 읽는 일이 많아서다. 폴더 경로만 있으면 치지 않는다.
  - 문서 위치(`cfg.docsRoot`) 안의 `.md` 파일만 남긴다. 경로는 문서 위치 기준 상대 경로(`03-ideas/x.md`)로 바꾼다.
- 남기는 곳: `.siloroot/state/trail/<session_id>.jsonl`에 한 줄 `{"ts", "kind", "path", "agent"}`. `agent`는 서브에이전트일 때 훅 입력의 `agent_id`, 아니면 없음.
- 비우기: `UserPromptSubmit`에 백그라운드 훅(`scripts/trail.mjs --reset`)을 더해 그 세션 파일을 비운다. 이때 7일 넘은 다른 세션 파일도 지운다(AI가 정함).
- 경로와 명령 내용 말고는 남기지 않는다. Bash 명령 문자열 자체는 남기지 않는다.

### 4.2 전달 (뷰어 서버)

- `viewer/serve.mjs`가 `state/trail/` 폴더를 지켜본다. 바뀌면 가장 최근에 바뀐 세션 파일을 읽어 `/events`로 `event: trail` 이름을 단 알림을 보낸다. 지금 쓰는 이름 없는 알림(문서 변경)과 섞지 않는다.
- `GET /trail`은 지금 흔적을 돌려준다. 연결 화면을 처음 열거나 새로 고칠 때 쓴다.
- 세션이 여럿이면 가장 최근에 움직인 세션의 흔적만 보낸다(AI가 정함).

### 4.3 화면 (연결 그래프)

시안 `shared/ideas/live-reading-graph-mockup.gif`, 덧그린 스크립트 `shared/ideas/live-reading-graph-mockup.js`가 기준이다. 모든 모양은 뷰어에 이미 있는 것을 쓴다.

| 부분 | 모양 | 뷰어에서 가져온 것 |
| --- | --- | --- |
| 색 | 읽음은 `--accent`, 고침은 `--flash-bar` | 고른 점의 선 색, 바뀐 줄 띠 색 |
| 흔적 선 | 앞 문서에서 다음 문서로 휜 선. 화살표 없음. 0.3초 뒤 0.9초 동안 출발 쪽에서 도착 쪽으로 색이 차오른다. 오래될수록 흐려진다(최소 0.3) | 새 선 `path.born`의 그어지는 움직임 |
| 도착한 점 | 색이 다 차면 둘레와 번호가 켜진다. 번호는 거쳐 간 차례이고 여러 번이면 `2·6`. 고침이 하나라도 있으면 고침 색 | 마우스를 올린 점의 둘레와 굵은 이름 |
| 가장 최근 점 | 둘레가 퍼진다 | 새 점의 `fvhalo` |
| 순서 목록 | 오른쪽 아래 상자. 제목("이번 답에서 거쳐 간 문서"), 설명, 개수는 고정, 목록만 스크롤. 목록 높이는 3줄(한 줄 28px)로 고정, 비었을 때도 같은 크기. 새 항목이 생기면 맨 아래로 부드럽게 내린다. 가장 최근 줄은 바탕색. 서브에이전트 줄에는 칩. 줄을 누르면 그 점을 고른다 | 정보 상자 `.ginfo`, 칩 `.chip`, 목록 줄 `.lnk` |
| 목록 자리 | 알림 상자(`#toast`, 창 오른쪽 아래 16px 고정)가 뜨는 높이보다 위. 알림 상자 높이는 실제로 재서 정한다(문구가 두 줄이 되어도 겹치지 않게) | |
| 켜고 끄기 | 오른쪽 도구 줄 "맞춤" 아래 "흔적" 단추. 켜짐이 기본. 그래프 설정(`fv-graph3`)에 함께 저장 | 도구 줄 단추 |
| 서브에이전트 | 점에 마우스를 올리면 "N번 · 서브에이전트가 읽음" | 이름표 `.tip` |
| 비움 | 새 메시지로 비워지면 알림 상자에 "새 메시지 · 흔적을 비웠어요" | 알림 상자 `toast()` |

- 점을 끌거나 확대, 이동하면 흔적 선과 번호가 점을 따라간다. 그래프 실시간 갱신(새 문서, 지운 문서)이 와도 흔적은 남는다.
- 필터로 숨긴 점은 그래프에 그리지 않고 목록에만 남긴다. 선은 보이는 앞뒤 점끼리 잇는다(AI가 정함).
- 흔적에 든 문서가 그래프에 없으면(예: 공통 문서를 끈 경우) 목록에만 남긴다.

### 4.4 마무리

- 테스트: `scripts/trail.mjs`(경로 바꾸기, Bash 경로 찾기, 문서 밖 무시, 비우기와 7일 정리), `serve.mjs`(`/trail`, `event: trail`), `hooks.json`(두 훅과 `async`).
- README 두 벌(`README.md`, `README.ko.md`)에 흔적 기능을 더한다.
- 버전은 기능이 늘었으므로 둘째 자리를 올린다. 다른 세션의 업데이트 장치(0.4.0, 브랜치 `feat/update-migration`)와 PR #21(0.3.1)이 먼저 머지되는지 보고 PR을 올릴 때 정한다.
- 작업은 최신 `origin/main`에서 딴 브랜치 `feat/live-reading-trail`에서 한다. 이 폴더는 PR #21 브랜치에 있으므로 따로 워크트리를 만든다(AI가 정함).

## 5. 만드는 사람에게 맡기는 것

- 흔적 그리기 코드를 `viewGraph` 안 어디에 끼울지, 끌기와 확대에 어떻게 따라가게 할지.
- 좁은 화면(760px 이하)에서 아래로 가로로 놓이는 폴더 범례와 목록 상자가 겹치지 않게 하는 법.
- `InstructionsLoaded` 훅으로 자동으로 불러오는 `CLAUDE.md`도 흔적에 넣을 수 있는지. 되면 넣고, 안 되면 아이디어 문서에 이유를 적는다.
- 백그라운드 훅 여럿이 같은 파일에 동시에 한 줄씩 붙일 때 줄이 섞이지 않는지 확인.
