# 업데이트를 update와 migrate로 나누기 (0.8.2)

`shared/decisions/update-split-by-weight.md`에서 정한 나눔을 어떻게 만들지. 바탕이 되는 업데이트 장치(백업, 마이그레이션 틀, 맞추기)는 `shared/design/update-migration-decision-design.md`에 있고 그대로 쓴다.

## 목표

- 사용자는 버전이 오를 때 `/siloroot:update` 하나만 돌린다. 플러그인 올리기, 뷰어 서버 바꾸기, 관리 블록 맞추기까지 끝난다.
- 패치 업데이트에서 마이그레이션 절차를 읽지 않는다.
- 업데이트가 끝나면 이번 버전에 무엇이 바뀌었는지 보인다.
- 할 일이 없는데 뜨는 업데이트 알림을 없앤다.

## 하지 않는 것

- 새 스킬과 훅을 지금 세션에 바로 싣기. Claude Code는 플러그인을 올린 뒤 재시작해야 적용한다. 끝에 "새 세션부터 적용"이라고 알린다.
- 마이그레이션 자체(001~003)와 백업 방식 바꾸기.
- 옛 배치(flat) 호환 코드 걷어 내기. 따로 정한다.

## 확인한 사실 (2026-11-25)

- 플러그인은 프로젝트 범위로 깔린다. 프로젝트마다 버전이 다를 수 있다(이 PC: 이 저장소 0.8.0, 다른 두 폴더 0.2.0과 0.7.0).
- `claude plugin list --json`은 프로젝트마다 `version`, `scope`, `installPath`, `projectPath`를 준다. `claude plugin update <id> --scope project --json`이 있고, 새 목록은 `claude plugin marketplace update`로 먼저 받는다.
- 홈과 홈 뷰어 서버는 여러 프로젝트가 같이 쓴다. 지금 서버 바꾸기는 옛 버전만 끄고 더 새 버전은 그대로 둔다(`viewer/autostart.mjs`).
- 뷰어 화면은 다시 붙은 서버의 버전이 바뀌면 스스로 새로 읽는다.
- 저장소에 버전별 변경 기록(CHANGELOG)이 없다.

## /siloroot:update 흐름

1. **새 버전 보기.** 이 프로젝트의 설치 정보(`claude plugin list --json`에서 `projectPath`가 이 폴더인 것)를 읽는다. 목록을 새로 받고(`claude plugin marketplace update <마켓플레이스>`) 더 새 버전이 있는지 본다.
   - `--plugin-dir`로 불러온 개발 플러그인이거나 설치 정보가 없으면 이 단계를 건너뛴다.
2. **올리기.** 새 버전이 있으면 "0.8.1 → 0.8.2로 올릴까요?"를 묻고, 승인하면 `claude plugin update siloroot@<마켓플레이스> --scope project --json`. 마켓플레이스가 선언한 명령 확인이 나오면 사용자에게 보이고 사용자가 정한다(대신 승인하지 않는다).
3. **새 버전으로 이어 가기.** 올렸으면 이 세션에 실린 옛 스크립트가 아니라 새 `installPath`의 `scripts/update.mjs`를 부른다. 이후 단계는 모두 새 스크립트가 한다.
4. **맞추기.** 지금의 `--plan`/`--apply` 맞추기(관리 블록, 빠진 파일, 빠진 줄, 안내 문서 표 항목). 홈도 맞춘다. 단 홈의 `plugin`이 이 플러그인보다 새것이면 홈은 건드리지 않는다(더 새 버전 프로젝트가 이미 맞췄다).
5. **서버 바꾸기.** 이 프로젝트와 홈의 뷰어 서버가 새 버전보다 옛것이면 끄고 새 버전으로 켠다. 브라우저는 새로 열지 않는다. 열린 탭은 스스로 새로 읽는다.
6. **바뀐 것 보이기.** CHANGELOG에서 옛 버전 다음부터 새 버전까지의 항목을 짧게 보인다.
7. **옮길 모양이 있으면** "작업 공간 모양 4 → 5로 옮길 것이 있습니다. `/siloroot:migrate`로 미리 보고 옮길 수 있습니다"라고 알리고 끝낸다. update는 마이그레이션을 돌리지 않는다.
8. 작업 일지에 한 줄, 끝에 "새 스킬과 훅은 새 세션부터"를 알린다.

## /siloroot:migrate 흐름

지금 스킬의 마이그레이션 부분(1~3-3단계, 6~7단계의 마이그레이션 쪽, 9~12단계)과 되돌리기를 옮긴다. 스크립트는 지금 `scripts/update.mjs`의 마이그레이션 경로를 그대로 쓴다.

- 002 전용 단계(11, 12)는 스킬 본문에서 빼서, 마이그레이션 계획의 `notes`나 마이그레이션별 안내 파일로 옮긴다. 그 마이그레이션이 있을 때만 읽는다.
- 앞머리 설명에 모양 3 → 4(003)를 더한다.
- 옮기기 전에 셸이 옮길 폴더 안에 있으면 프로젝트 맨 위로 나오라고 알린다(002 첫 시도의 EBUSY).
- 되돌리기는 migrate에 둔다. 맞추기만 한 백업도 migrate의 되돌리기로 돌린다.

## 세션 시작 알림

| 상황 | 지금 | 바꾼 뒤 |
| --- | --- | --- |
| 옮길 모양이 있음 | 알림 | 알림(`/siloroot:migrate`를 가리킴) |
| 설정의 `plugin`이 설치된 버전과 다르고, 맞출 것이 있음 | 알림 | 알림(`/siloroot:update`) |
| 설정의 `plugin`만 다르고 맞출 것이 없음 | 알림 | 알리지 않고 훅이 `plugin`만 적는다 |
| 홈의 `plugin`이 이 플러그인보다 새것 | 알림 | 알리지 않는다 |

새 플러그인 버전이 나왔는지는 세션 시작 때 보지 않는다(네트워크가 들고 훅 제한 시간이 짧다). update를 돌릴 때 본다.

## 바뀐 것 기록 (CHANGELOG)

- 저장소 맨 위 `CHANGELOG.md`. 버전마다 `## 0.8.2` 아래 사용자가 알아볼 말로 몇 줄.
- 내보내기 PR에서 쓴다. 저장소 `CLAUDE.md`의 "버전과 내보내기"에 한 줄 더한다.
- 0.8.1까지의 항목은 이번에 한 번 채운다(0.8.0, 0.8.1 정도).

## 코드에서 바뀌는 곳

| 곳 | 바뀌는 것 |
| --- | --- |
| `skills/update/SKILL.md` | 가벼운 흐름으로 다시 쓴다 |
| `skills/migrate/SKILL.md` | 새로 만든다(지금 스킬의 마이그레이션과 되돌리기) |
| `scripts/update.mjs` | 마이그레이션을 돌리지 않는 맞추기 경로, 플러그인 정보 읽기, 서버 바꾸기, CHANGELOG 항목 꺼내기 |
| `viewer/autostart.mjs` | 서버 바꾸기(`ensureServer`)를 `lib/`로 빼서 update와 같이 쓴다 |
| `lib/update-check.mjs`, `viewer/notify.mjs` | 위 알림 표 |
| `CHANGELOG.md`, 저장소 `CLAUDE.md`, README 두 벌 | 기록과 안내 |

## 테스트

- 맞출 것 없는 버전 차이: 알림이 없고 `plugin`만 적힌다.
- 홈이 더 새 버전: 알림 없음, 맞추기에서 홈을 건드리지 않음.
- 옮길 모양이 있을 때 update는 마이그레이션을 돌리지 않고 migrate를 가리킨다.
- 서버 바꾸기: 옛 버전 서버를 끄고 새로 켜며, 더 새 버전 서버는 그대로.
- CHANGELOG에서 두 버전 사이 항목만 꺼낸다.
- 플러그인 올리기는 `claude` 명령을 부르는 부분이라 단위 테스트에서는 가짜 명령으로 바꿔 본다.

## 정한 것 (사용자, 2026-11-25, 제안대로)

- update는 플러그인을 올리기 전에 묻는다.
- 바뀐 것 목록은 이번에는 update 결과에만 보인다(뷰어는 나중).
- 맞출 것 없는 버전 차이에서는 세션 시작 훅이 설정의 `plugin` 칸을 올려 적는다. 올리기만 하고 내리지 않는다(프로젝트, 홈 모두).

## 구현하며 덧붙인 것 (AI)

- `claude` 명령(목록 받기, 설치 목록, 플러그인 올리기)은 스킬이 Bash로 부른다. 스크립트는 그 JSON 결과를 읽기만 한다. 마켓플레이스가 선언한 명령 확인이 사용자 눈에 보이게 하려고, `-y`는 쓰지 않는다.
- 플러그인을 올린 뒤에는 늘 새 버전의 `skills/update/SKILL.md`를 읽고 "올린 뒤" 절부터 이어 간다. 이 세션에 실린 스킬 글은 옛 버전이라서다.
- 바뀐 것 범위는 설정의 `plugin`이 아니라 올리기 전후의 설치 버전으로 잡는다(훅이 `plugin`을 조용히 올리므로).
- 0.8.2 자체는 0.8.1 스킬이 올리지 못하므로 예전 세 단계로 받는다.
- 세션 시작 훅이 번호를 조용히 올릴 때 옛 번호를 `state/update-from.json`에 남긴다. 플러그인을 스킬 밖에서 올려도 `--changes`가 그 기록으로 바뀐 것을 보인다.
- 개발 플러그인(`--plugin-dir`)의 `--servers`는 홈 서버를 건드리지 않는다. 홈 서버는 다른 프로젝트도 같이 쓴다(구현 중 시험하다 실제 홈 서버가 저장소 코드로 바뀐 일이 있어 넣었다).
