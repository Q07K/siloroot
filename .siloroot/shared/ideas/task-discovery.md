# 업무 발견: 지금 할 일을 AI가 찾기

- 2026-11-27 외부 AI가 낸 자율 업무 관점 검토에서 나옴. 묶음은 `shared/ideas/autonomous-work.md`
- 외부 의견이 가장 중요하다고 꼽은 부분

## 외부 의견이 말한 것

- 사람이 일을 등록하면 AI가 하는 구조가 아님
- AI가 목표, 문제, 요구사항, 결정, 지식을 보고 일 자체를 찾음
- 예: 로드맵에 "LLM API 서버 응답 지연을 5초 이내로"만 적혀 있음
  - 로드맵 목표, 시스템 개요, 이슈를 견줌 → 기준 측정값이 없음을 찾음
  - 업무 셋을 만듦: 지금 응답 시간 재기, 구간별 병목 보기, 개선 방안 조사
  - 하다가 새 문제를 찾으면 이슈를 만듦(예: 임베딩 모델이 요청마다 초기화됨)
  - 구조를 바꾸는 결정은 승인을 기다림
  - 승인 뒤 구현, 테스트, 성능 비교, PR
  - 측정값, 결정 근거, 구현 방식, 다시 쓸 지식을 각 자리에 남김
- 사람은 목표를 정하고 중요한 결정에만 들어옴
- 관계를 따라가며 던질 질문
  - 지금 목표를 못 이루는 까닭은
  - 어떤 요구사항에 맞는 업무가 빠졌나
  - 지난 결정의 전제가 바뀌었나
  - 다른 프로젝트에서 이미 푼 문제인가
  - 지금 할 수 있는 가장 값진 일은

## 지금 있는 것 (AI, 2026-11-27 확인)

| 무엇 | 지금 | 빈 곳 |
| --- | --- | --- |
| 로드맵 "지금" 칸 | 진행 중 기능과 상태 한 줄 | 남은 일은 사람이 읽고 정함 |
| 요구사항 | 목표와 비목표, 거쳐 온 길 | 목표 대비 무엇이 빠졌는지 보는 장치 없음 |
| 확인할 것 | 사용자 확인이 필요한 것 | AI가 할 일이 아니라 사용자에게 물을 것 |
| 인수인계 아이디어 | 다음 할 일 제안: 로드맵과 열린 질문에 이미 적힌 것을 모아 보임(`shared/ideas/session-handoff.md`) | 적힌 것을 모으기만 함. 빈 곳을 새로 찾지 않음 |
| 관계 | `related`, 본문 경로. 종류 있는 선은 아이디어(`shared/ideas/edge-meaning.md`) | 종류가 없어 "요구사항에 구현이 빠짐" 같은 질문을 못 따라감 |

## 인수인계와 다른 점 (AI)

| | 인수인계의 다음 할 일 제안 | 업무 발견 |
| --- | --- | --- |
| 하는 일 | 적힌 일을 모아 보임 | 목표와 지금 상태 사이 빈 곳에서 새 일을 만듦 |
| AI 판단 | 거의 없음 | 큼. 틀릴 수 있음 |
| 순서 | 먼저 | 인수인계가 모은 것을 이어 씀 |

## 생각해 볼 방향 (AI, 정하지 않음)

- 처음에는 찾기만 하고 만들지 않음
  - 찾은 것을 후보로 보이고 사용자가 고름
  - 글쓰기 규칙 후보 → 승인 흐름과 같음
- 신호를 둘로 나눔. 구현 점검에서 나눈 방식과 같음
  - 스크립트로 볼 것: 요구사항에 이어진 구현 계획이 없음, 열림 이슈가 오래됨, 로드맵 "지금" 칸인데 요구사항 `status`가 완료
  - AI가 판단할 것: 결정 전제가 바뀌었나, 목표를 못 이루는 까닭
  - 스크립트 쪽은 토큰이 들지 않음
- 선 종류(근거, 영향, 구현)가 정해지면 스크립트로 볼 신호가 늘어남
- 다른 프로젝트에서 푼 문제 찾기
  - 홈과 다른 작업 공간을 건너 찾아야 함
  - 공유 문서가 개인 문서를 가리키지 않는 방향 원칙과 함께 봐야 함

## 열린 질문

- 찾은 업무를 어디에 두나: 후보로만 보일지, 업무 객체로 만들지(`shared/ideas/task-objects.md`)
- 언제 찾나: 세션 시작, 요청할 때, 예약 실행
- 찾은 것이 틀렸을 때 누가 어떻게 거르나
