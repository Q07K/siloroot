# 이미 문서가 있는 프로젝트에 SiloRoot 얹기

- 2026-11-27 다른 세션 세 곳의 "이 프로젝트에 SiloRoot를 설치할까" 검토 결과를 보고 나옴
- 세 곳 모두 "지금은 설치하지 않는 게 낫다"로 끝남. 새로 시작하는 프로젝트가 아니면 도입이 꺼려짐
- `shared/ideas/project-bootstrap.md`는 기존 프로젝트에서 문서를 새로 만들어 내는 이야기. 이 문서는 이미 있는 문서 체계와 함께 사는 이야기

## 검토한 프로젝트 (이름은 뺌)

| 프로젝트 | 모양 | 결론 |
| --- | --- | --- |
| A | 코드 저장소. 결정·구조·연구 문서가 `docs/`와 `AGENTS.md` 체계에 있음 | 남는 이득이 작업 일지와 확인할 것뿐. `AGENTS.md` 몇 줄로 대신할 수 있음 |
| B | 업무 자료 폴더. 마크다운 약 540개, 유형/건/칸 구조, 건마다 결정·요구 문서가 있음 | 지금 설치는 권하지 않음 |
| C | 회사 저장소의 하위 폴더. 조사·결정 문서 약 30개를 평면 폴더에 날짜 붙여 둠 | 버그를 고치고 문서 자리를 정한 뒤에만 |

## 걸림돌을 원인별로

| 걸림돌 | A | B | C | 확인 |

## 공통 뿌리 (AI)

- init이 "SiloRoot가 문서 구조를 가진다"를 전제로 함
  - 문서 뿌리, 자리 표, 행동 규칙, 홈 연결을 한 번에 모두 켬
- 기존 문서 체계가 있으면 둘 중 하나가 됨
  - 기존 문서를 못 봄
  - 기존 규칙과 다툼
- 그래서 얻는 것(그래프, 흔적)은 기존 문서에 닿지 않고, 비용(규칙, 훅, 홈)은 다 따라옴

## 개선 방향 (AI 제안, 정하지 않음)

"전부 켜기"를 "단계별로 켜기"로 바꿈. 앞 단계일수록 기존 규칙을 건드리지 않음.

| 단계 | 켜는 것 | 켜지 않는 것 | 푸는 걸림돌 |
| --- | --- | --- | --- |
| 1. 보기만 | 기존 폴더를 문서 뿌리로 읽기. 그래프, 흔적, 댓글 | 관리 블록, 자리 폴더, 홈 연결, 속성 경고 | 안 보임, 규칙 두 벌, 홈 섞임, 루트 파일 |
| 2. 기록 켜기 | 작업 일지, 확인할 것만 담은 얇은 블록. "이 프로젝트의 규칙이 먼저"를 한 줄로 | 자리 표 전체, 나누기 규칙 | 늘 드는 비용 일부 |
| 3. 자리 잇기 | 결정·요구·이슈 자리를 기존 위치로 가리키는 설정(폴더, 또는 건마다 파일 이름 패턴) | | 규칙 두 벌을 하나로 |
| 4. 전부 | 지금 init과 같음 | | 새 프로젝트 |

단계와 따로 할 것:

- 하위 폴더 git 제외 버그 수정(이미 내보낸 버전의 버그라 바로 패치)
- init 전 진단: 기존 규칙 파일, 문서 폴더, git 맨 위 위치, 겹치는 규칙을 보고 단계를 추천
  - 이번 세 세션이 손으로 한 분석을 init이 대신함
- 회사·고객 작업 공간에서 홈 연결 끄기
- 세션마다 뷰어 켜기를 끄는 설정

## 지금 코드에서 쓸 수 있는 것 (AI 확인)

- 마크다운 링크 `[글](경로)`도 선이 됨(`lib/links.mjs`). 기존 문서끼리의 링크가 그대로 그래프가 됨
- 문서 뿌리 = 폴더 자체인 배치(`flat`)가 이미 있음. 홈이 이렇게 씀(`scripts/init.mjs`)
- 속성 없는 문서도 점으로 나옴. 대신 문서마다 "type 속성이 없음" 경고가 남(`viewer/build.mjs`). 보기만 단계에서는 꺼야 함
- 훅은 `.siloroot/config.json`이 없는 폴더에서 아무것도 안 함

## 열린 질문

- 기존 프로젝트에서 SiloRoot로 얻고 싶은 것이 무엇인지: 기존 문서의 그래프와 흔적인지, 기록 규칙인지. 이것으로 어느 단계부터 만들지 정해짐
- 보기만 단계에서 문서 뿌리를 하나로 둘지, 여러 폴더를 받을지
- 자리 잇기에서 "건마다 결정 문서"처럼 폴더가 아닌 패턴을 어디까지 받을지
