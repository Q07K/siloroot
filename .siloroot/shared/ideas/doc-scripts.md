# 문서 조회와 초안을 스크립트로

사용 기록 기능(PR #19, 0.3.0)을 만든 까닭을 이야기하다 나왔다. 논의 과정은 private/discussions/2026-11-24-doc-scripts.md에 있다.

## 사용자 생각

문서를 조회하거나 새 문서를 만들 때 같은 일에 토큰이 되풀이해 들어간다면, 초안을 만드는 스크립트(도구)를 미리 만들어 두고 Claude가 그것을 쓰게 하면 어떨까. 사용 기록은 이것이 맞는지 볼 근거를 얻으려고 만들었다.

## AI가 본 것

지금 문서를 만들 때 Claude는 `metadata-guide.md`와 폴더 `README.md`를 읽고(입력), 같은 모양의 속성, 목차 줄, `related`, 작업 기록 줄을 매번 새로 쓴다(출력). 이 부분은 규칙이 정해져 있어서 스크립트가 같은 결과를 토큰 없이 낼 수 있다.

| 스크립트가 맡을 수 있는 것 | Claude가 계속 맡을 것 |
| --- | --- |
| 폴더에 맞는 `type`, `status`, `created`가 든 속성 | 본문 내용(설명, 판단, 문답) |
| 파일 이름 정하기 | 어느 문서와 이어질지 고르기 |
| 폴더 목차(home:study/README.md 등)에 줄 더하기 | 요약 한두 줄 |
| `related`를 양쪽 문서에 넣기 | |
| `private/log/changelog.md`에 날짜 절과 줄 더하기 | |
| 속성 점검 | |

조회도 같다. `viewer/build.mjs`가 이미 모든 문서를 읽어 경로, 제목, 속성, 연결을 `state/data-private.json`에 모아 둔다. 이것을 짧게 돌려주는 조회 스크립트가 있으면, Claude가 여러 파일을 검색하고 통째로 읽는 대신 목록 한 번으로 고를 수 있다.

## 주의할 점

- 스크립트를 부르는 것도 토큰이 든다. 명령과 출력이 맥락에 들어가므로 출력을 짧게(경로 한 줄, 필요한 칸만) 해야 남는다.
- 절감은 스크립트를 만드는 것만으로 생기지 않는다. 스킬 본문(`note`, `feedback` 등)이 규칙 문서를 읽고 직접 쓰라고 하는 대신 스크립트를 부르라고 바뀌어야 한다.
- 초안은 뼈대다. 본문을 스크립트가 쓰는 것은 아니다.

## 지금 있는 숫자 (2026-11-24)

이 저장소의 지난 대화 두 개를 사용 기록으로 돌려 본 것이다. `turn:siloroot-docs`(스킬 없이 `.siloroot/` 문서를 다룬 턴) 28턴, 응답 102번.

| 항목 | 값 |
| --- | --- |
| 비용 (API 정가 환산, Opus 5.5) | $8.62, 턴당 약 $0.31 |
| 비용 나눔 | 캐시 읽기 48%, 출력 28%, 캐시 쓰기 24% |
| 응답마다 캐시에서 다시 읽은 대화 | 평균 약 20만 토큰 |
| 출력 토큰 | 121k |
| 도구 결과가 들여온 글자 | 69k, 그 가운데 `.siloroot` 문서 몫 38k (턴당 약 1.4k자) |

- 문서를 찾아 읽어 들이는 내용은 작다.
- 가장 큰 것은 호출 횟수다. 응답마다 대화 전체를 캐시에서 다시 읽는다(설명은 home:study/prompt-cache-tool-call-cost.md).
- 그다음이 출력이다. 속성, 목차, `related`, 작업 기록처럼 정해진 모양도 Claude가 매번 쓴다.
- 그래서 스크립트는 여러 단계를 한 번의 호출로 줄이고, 정해진 모양의 출력을 맡을 때 남는다. 숫자가 이렇게 정리되기까지의 과정은 논의 기록에 있다.

## 열린 질문

- 비슷한 생각: Cloudflare의 Code Mode는 도구를 하나씩 부르는 대신 모델이 API를 부르는 코드를 짜게 해서 도구 설명과 중간 결과 토큰을 줄인다. 공부 노트 home:study/cloudflare-code-mode.md.

- 스크립트를 어느 단위로 둘지: 문서 종류마다(공부 노트, 아이디어, 논의) 하나씩, 아니면 종류를 인자로 받는 하나.
- 조회 스크립트가 `data-private.json`을 쓸지, 문서를 직접 읽을지. 앞쪽은 빠르지만 뷰어 생성물이 최신이어야 한다.
