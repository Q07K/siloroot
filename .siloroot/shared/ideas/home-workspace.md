# 홈과 모드

`shared/ideas/workspace-modes.md`의 "홈과 모드" 절을 따로 나눴다(2026-11-24). 모드와 공부 노트의 자리는 그 문서에, 논의 과정은 private/discussions/2026-11-24-init-modes.md에 있다.

홈이 생기면 두 모드가 각자 맡을 곳이 분명해진다.

| 모드 | 만드는 곳 | 개수 | 담는 것 |
| --- | --- | --- | --- |
| personal | 홈 작업 공간 | 사람마다 하나 | 공부 노트(개념), 사용자 정보, 글쓰기 규칙, 개인 아이디어 |
| project | 저장소 안 `.siloroot/` | 저장소마다 하나 | 공유 영역(컨벤션, 결정, 작업 지식), 개인 영역(프로젝트 메모, 피드백) |

- project 모드로 초기화하면 홈을 찾아 잇는다. 홈이 없으면 만들지 묻는다.
- project 작업 공간의 AI는 사용자 정보와 글쓰기 규칙을 홈에서 불러온다. 프로젝트마다 따로 두지 않는다.
- 모드는 서로 막지 않는다. 홈에도 프로젝트 같은 일을 적을 수 있고, 프로젝트에서도 공부가 생긴다(개념은 홈으로).

### 홈은 어느 폴더인가

사용자가 물었다: 홈은 폴더 어디를 뜻하나, 프로젝트 안에서 홈을 나누나. AI 답: 프로젝트 안이 아니라 프로젝트 바깥의 폴더 하나다.

```
C:\Users\<나>\siloroot-home\      홈 (personal). 사람마다 하나
C:\Users\<나>\github\payment\     프로젝트 저장소
  .siloroot\                      project 작업 공간
C:\Users\<나>\github\search\
  .siloroot\                      project 작업 공간
```

AI 제안(정하지 않음):

- 위치는 personal 초기화 때 사용자가 고르고, 기본값은 사용자 폴더 아래 `siloroot-home`이다. 숨김 폴더보다 보이는 폴더가 낫다. 사용자의 노트이고, 따로 git 저장소로 만들어 백업하거나 여러 컴퓨터에서 맞출 수도 있다.
- 홈 위치는 사용자 단위 설정 한 곳에 적고, project 작업 공간은 그 설정을 읽어 홈을 찾는다.
- 지금 이 저장소처럼 프로젝트 안에 공부용 작업 공간을 둔 경우는, 홈이 생기면 공부 노트와 사용자 정보를 홈으로 옮기는 길이 필요하다.

### 여러 프로젝트의 공부가 홈에 쌓이면, 그래프는

사용자가 물었다: 여러 프로젝트에 SiloRoot를 init하면 모든 프로젝트에서 생긴 공부가 홈에 쌓이나. 그러면 웹 그래프는 어떻게 보여 주나.

쌓이는 것은 맞다. 다만 쌓이는 것은 개념뿐이고, 사건 문서는 각 프로젝트에 남는다. AI 제안(정하지 않음):

- 뷰어는 지금처럼 작업 공간마다 따로 연다. 모든 작업 공간을 한 그래프에 합치지 않는다. 너무 커지고, 팀이 보는 프로젝트와 내 홈이 한 화면에 섞인다.
- 다른 작업 공간의 문서는 이어진 것만 한 걸음까지 "바깥 점"으로 보인다. 흐리게 그리고, 작업 공간 이름으로 묶는다. 누르면 그 작업 공간의 뷰어로 간다.
- 홈 그래프에서는 프로젝트 문서가 프로젝트 이름별 묶음(예: `payment`, `search`)으로 바깥에 붙는다. "이 프로젝트에서 만난 공부만 보기"로 거를 수 있다(`met_in` 선을 따라, 선 종류는 `shared/ideas/edge-meaning.md`).
- 홈에는 노트가 계속 늘어나니, 분야(`tags` 첫 낱말)와 프로젝트로 거르는 것이 기본 도구가 된다.
- 바깥 점을 그리려면 홈이 프로젝트 위치를 알아야 한다. project 초기화 때 사용자 단위 설정에 그 작업 공간을 등록한다(홈 위치를 적는 그 설정).

```
홈 그래프
  [분야: Rust]  rust-lifetime ── met_in ──▶ ( payment: retry-queue-lifetime )  ← 흐린 바깥 점
                rust-traits   ── met_in ──▶ ( search: index-builder )
```

사용자가 물었다: 그러면 웹 하나에서 여러 프로젝트 뷰를 보게 되나. AI 답:

| 방식 | 모습 | 장단 |
| --- | --- | --- |
| 지금처럼 작업 공간마다 따로 | 작업 공간마다 뷰어 서버와 포트가 따로 있다(`config.json`의 `port`). 바깥 점을 누르면 다른 주소의 뷰어가 열린다 | 지금 구조 그대로다. 프로젝트가 늘면 탭과 포트가 늘고, 서로 오가기가 번거롭다 |
| 웹 하나에서 전환 | 뷰어 하나가 등록된 작업 공간을 모두 안다. 위쪽에서 홈, payment, search를 골라 하나씩 본다. 그래프를 합치지는 않고, 바깥 점은 누르면 그 작업 공간으로 전환된다 | 주소 하나로 다 본다. 서버 하나가 여러 폴더를 읽어야 하고, 프로젝트 안에서 뷰어를 열면 그 프로젝트가 먼저 보여야 한다 |

AI는 웹 하나에서 전환하는 쪽을 추천했다.

**정함 (2026-11-24, 사용자):** 작업 공간마다 따로 연다. 홈의 공부와 프로젝트별 연결이 화면에서 어떻게 보일지는 시안으로 본다.

시안(1판, 실제 뷰어 코드를 복사해 예시 데이터로 만듦):

| 안 | 모습 |
| --- | --- |
| 0안 지금 | 홈 문서만 보이고 프로젝트 연결은 안 보인다 |
| 1안 바깥 묶음 | 프로젝트 문서가 흐린 점선 점으로, 프로젝트 이름별 묶음("↗ payment (바깥)")에 붙는다. `met_in` 선은 굵게 |
| 2안 이름표 | 바깥 점 없이 노트 이름 옆에 프로젝트 이름표만 붙는다 |
| 3안 프로젝트로 거르기 | 1안 위에 "만난 곳으로 보기" 칩. 고른 프로젝트와 이어진 것만 진하고 나머지는 흐리다 |

프로젝트 쪽(payment)은 1안 방식으로, 홈 노트가 "↗ home (바깥)" 묶음으로 붙는다. 고른 안은 아직 없다.

시안의 예시 프로젝트(payment, search, admin)는 한 서비스의 기능처럼 읽혀 프로젝트 단위를 흐렸다. 다음 판은 단위를 정한 뒤 실제와 비슷한 예시로 다시 만든다.

## 열린 질문

- 위 "홈과 모드" 제안이 맞는지.
- 홈의 실제 위치와, 프로젝트에서 홈 문서를 가리키는 경로 적는 법(지금 뷰어는 작업 공간 밖을 가리키는 연결을 버린다).
