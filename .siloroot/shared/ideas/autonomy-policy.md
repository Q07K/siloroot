# 자율 단계와 실행 허용 정책

- 2026-11-27 외부 AI가 낸 자율 업무 관점 검토에서 나옴. 묶음은 `shared/ideas/autonomous-work.md`

## 외부 의견이 말한 것

- 자율 단계 다섯. 외부 의견 스스로 공식 분류가 아니라 SiloRoot 방향을 설명하려고 나눈 것이라고 밝힘

| 단계 | 모습 |
| --- | --- |
| 0 기록형 | 사람이 일하고 AI가 기록. "현재 주요 구조"라는 표시가 붙음 |
| 1 보조형 | AI가 다음 업무를 추천 |
| 2 실행형 | 사람이 승인한 업무를 AI가 함 |
| 3 자율형 | AI가 업무를 찾고, 만들고, 하고, 검증. "개발 목표 제안"이라는 표시가 붙음: 외부 의견이 SiloRoot의 다음 목표로 꼽은 단계 |
| 4 목표 기반 자율형 | 맡긴 목표 안에서 계획과 업무를 계속 고침 |

- 프로젝트마다 자율 단계와 실행 권한을 고름
- 업무별 정책 예

| 업무 | 정책 |
| --- | --- |
| 기술 조사, 문서 정리, 미해결 이슈 분석, 테스트 코드 작성 | 자동 허용 |
| 코드 수정 | 정한 범위 안에서 허용 |
| PR 만들기 | 정책에 따라 |
| 구조 변경, 운영 배포, 비용이 드는 자원 만들기 | 승인 필요 |

- 새 폴더 `policies/`에 둠

## 생각해 볼 방향 (AI, 정하지 않음)

- 정책은 새 폴더 대신 컨벤션 문서 하나로 둠(예: 자율 실행 허용)
- 정책 문서는 AI가 따르는 약속. 실제로 막는 것은 Claude Code 권한
  - SiloRoot가 권한을 넓히거나 사용자 대신 승인하지 않음
  - 꼭 막아야 할 것은 사용자가 권한 설정이나 훅으로 고르게 안내함
  - 구현 점검의 "막는 관문은 사용자가 고름"과 같은 생각
- 단계를 한 번에 정하지 않고 관심사마다 켬
  - 업무 발견(1) → 승인한 업무 실행(2) → 루프(3)
  - 기존 프로젝트 도입에서 나온 단계별 켜기(`shared/ideas/existing-project-adoption.md`)와 비슷한 생각
