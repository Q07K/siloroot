# 쓰이는지 재기

- 2026-11-26 외부 제품 피드백(이탈 원인 가설) 검토에서 나옴
- 피드백 7절 "실제 이탈 원인을 확인하는 방법"과 P2 "절감 시간·토큰·반복 작업 표시"

## 피드백이 말한 것

- 사용자 동의를 받아 제품 사용 지표를 더함
- 뷰어를 다시 열지 않는 사용자와 플러그인을 아예 안 쓰는 사용자를 가름
  - 뷰어를 안 열어도 뒤에서 지식을 쓰고 있으면 떠난 것이 아님
- 떠난 사용자 5~10명에게 한 가지만 물음: "기존 방식으로 돌아갔을 때 아쉬웠던 기능이 있었나요?"
  - 없다면 편의 문제가 아니라 핵심 가치 문제일 가능성이 큼
- 아낀 시간·토큰을 보여 효과를 체감하게 함

## 지금 있는 것 (AI, 2026-11-26 확인)

| 무엇 | 남기는 것 | 남기지 않는 것 |
| --- | --- | --- |
| 사용 기록 `metrics.jsonl` | 단계 이름(문서를 건드린 턴은 `turn:siloroot-docs`), 시각, 걸린 시간, 토큰, 도구별 횟수·시간·결과 글자 수, 문서 도구 결과 글자 수(`docChars`), 스킬 이름, 세션 id | 문서 경로, 내용, 프롬프트(`lib/metrics.mjs`) |
| 흔적 `state/trail/` | 이번 답에서 읽고 고친 문서 경로 | 새 메시지에 지워짐 |
| 밖으로 보내기 | 없음. 모두 로컬 | |

## 지표마다 지금 낼 수 있나 (AI)

| 피드백 지표 | 지금 자료로 | 빈 곳 |
| --- | --- | --- |
| 설치 → 첫 초기화 완료율 | 못 냄 | 설치는 플러그인 밖. 여러 사람 자료 필요 |
| 초기화 → 첫 지식 생성 시간 | 한 사람 것은 냄(문서 `created`) | |

| 다음 날·7일 뒤 사용률 | 한 사람 것은 냄(사용 기록 날짜) | 여러 사람은 밖으로 보내야 함 |
| 만든 문서 대비 다시 쓴 문서 | 못 냄 | 문서 경로가 필요함. 흔적을 쌓아야 함: `shared/ideas/reuse-evidence.md` |
| SiloRoot 전후 처리 시간 | SiloRoot 쪽만 | SiloRoot 없이 쓴 기준선 없음 |
| 끄거나 지운 까닭 | 못 냄 | 인터뷰, 설문 |

## 주의할 점 (AI)

- 여러 사람 지표는 자료를 밖으로 보내야 함
  - 지금 원칙(로컬에만, 경로·내용 안 남김)과 부딪힘
  - 동의, 보낼 곳, 지우는 법을 따로 정해야 함
- 사용자가 몇 명인지에 따라 쓸모가 달라짐
  - 적으면 지표보다 인터뷰가 빠름
  - 사용자 답(2026-11-26): 피드백이 전제한 이탈은 다른 사용자가 아니라 본인 경험과 가설. 지금은 한 사람 로컬 지표 쪽에 무게
- 아낀 시간·토큰 보이기는 기준선이 먼저 있어야 함. 문서 스크립트의 기준선 단계(`shared/ideas/doc-scripts.md`)와 같은 자료

## 처음 뽑아 본 것 (2026-11-26)

- 이 저장소의 나흘치 기록으로 날짜별 턴, 문서를 건드린 턴 비율, 문서 몫을 뽑아 봄
- 문서를 건드린 턴이 85% 안팎이지만, 작업 일지 쓰기 때문이 많고 경로가 없어 읽기(활용)인지 쓰기(기록)인지 가를 수 없었음
- 매 턴 불러오는 규칙 문서가 4,106자에서 7,014자로 늘어남(11-24 → 11-26)
- 다음에 쓸모 있을 것: 문서 경로 없이 "읽기·쓰기 횟수"만 나눠 세기(경로 안 남김 원칙은 지킴)

## 읽기·쓰기 나눠 세기 (AI 안, 2026-11-26, 정하지 않음)

- 사용자가 처음 뽑아 본 기록 뒤 "이어서 보자"고 함
- 목표: "기록만 한 턴"과 "기록을 읽어 쓴 턴"을 가름

### 지금 두 셈

| 무엇 | 사용 기록 | 흔적 |
| --- | --- | --- |
| 문서 가르기 | 도구 입력에 `.siloroot` 글자가 있으면 문서 | `.md`만, 상태 폴더 빼고, 홈 문서 포함(`lib/trail.mjs` `toDocPath`) |
| 읽기·쓰기 | 안 가름 | Read는 읽음, Edit·Write는 고침, Bash 명령 글자의 경로는 읽음, `apply_patch`는 고침 |
| 경로 | 안 남김 | 남김 |
| 남는 기간 | 계속(5MB 넘으면 한 벌만 더) | 새 메시지에 비움. 다른 세션 파일은 7일 뒤 지움 |
| 못 잡는 것 | 홈 문서(`shared/issues/metrics-doc-detection.md`) | 스크립트, PowerShell로 다룬 문서(`shared/issues/trail-misses-scripts.md`) |

- 새로 만들지 않고 흔적의 가르기(`entriesFromHook`)를 사용 기록이 대화 기록의 도구 호출에 그대로 씀. 이슈 하나도 함께 풀림

### 안

| 안 | 턴마다 남기는 것 | 답할 수 있는 것 | 원칙과 맞나 |
| --- | --- | --- | --- |
| A. 횟수만 | 읽은 문서 수, 고친 문서 수 | 읽지 않고 쓰기만 한 턴 비율 | 경로 안 남김 그대로 |
| B. 자리별 횟수 | A + 자리 이름별 수(예: 결정 읽음 3, 작업 일지 고침 1) + 문서 밖 파일 고친 수 | 작업 일지만 쓴 턴 가르기. 결정·컨벤션을 읽고 코드를 고친 턴(활용 신호) | 자리 이름은 SiloRoot가 정한 폴더라 사용자 내용이 아님. 사용자가 더한 폴더는 "기타"로 묶음 |
| C. 흔적 쌓기 | 흔적을 비우지 않고 날짜별로 보관 | 문서마다 다시 쓰인 횟수, 첫 재사용까지 시간, 한 번도 안 쓰인 문서 | 경로가 남음. 흔적은 이미 로컬에 7일 경로를 남기므로 보관 기간 문제에 가까움 |

- **확정 (2026-11-26, 사용자):** B로 함. 결정 기록 `shared/decisions/metrics-count-by-slot.md`
- AI 추천: B부터
  - 피드백의 핵심 질문(기록이 일에 쓰이나)에 가장 싸게 가까워짐
  - 원칙을 바꾸지 않아도 됨
  - C는 근거 보이기(`shared/ideas/reuse-evidence.md`)를 만들 때 함께 봄
- 한계: 스크립트로 다룬 문서는 어느 안이든 못 잡음. 이 작업 공간처럼 node 스크립트로 문서를 많이 고치면 고친 수가 적게 나옴

## B안 미리 뽑아 본 것 (2026-11-26)

- 지난 대화 기록 28세션, 440턴에 B안 셈을 한 번 돌림. 값은 `shared/decisions/metrics-count-by-slot.md`
- 참고 문서를 읽고 코드를 고친 턴 5%, 읽지 않고 코드만 고친 턴 16%, 기록만 한 턴 46%
- 코드를 고친 세션의 절반만 고치기 전에 참고 문서를 읽음. 결정을 읽은 세션은 1개
