# 오늘 Claude와 한 일이 남는 작업 일지

`shared/ideas/doc-slots.md`에서 AI 작업 기록을 날짜별 문서(`worklog`)로 나누자는 이야기를 하다가, 사용자가 물었다: "저게 진짜 내가 오늘 어떤 작업을 클로드랑 했는지가 남는 건가?"

## 지금 작업 기록이 남기는 것과 못 남기는 것 (2026-11-25 기록으로 확인)

이 작업 공간의 2026-11-25 작업 기록은 37줄이다.

| 남는 것 | 못 남기는 것 |
| --- | --- |
| 파일을 바꾼 일의 AI 요약 한 줄 | 파일을 안 바꾼 문답("한 장이 오히려 빠르네?", "어떤 연산이 가장 비싸?" 등) |
| 정한 것의 경로 | 사용자가 무엇을 요청했는지(사용자의 말) |
| | 어느 세션에서 한 일인지. 여러 세션의 줄이 섞여 있다 |
| | 몇 시에 했는지. 줄 차례는 쓴 차례라 실제 흐름과 다르다 |
| | AI가 줄을 빠뜨리면 남지 않는다(AI 기억에 기댄다) |
| | 홈에서 한 일은 홈 작업 기록에 따로 있어 하루가 두 곳으로 갈린다 |

그래서 지금 모양으로는 "AI가 기억해서 적은, 파일을 바꾼 일의 목록"이지 "오늘 Claude와 한 일"이 아니다.

## 이미 훅이 모으는 것 (코드에서 확인, 2026-11-25)

사용자가 작업 기록이 "이번 답에서 거쳐 간 문서"(흔적)를 보이려고 만드는 것인지 물었다. 둘은 다른 것이다.

| 무엇 | 자리 | 누가 쓰나 | 얼마나 남나 |
| --- | --- | --- | --- |
| 작업 기록 | private/worklog/ | AI가 답을 마칠 때 손으로 | 계속 |
| 흔적(이번 답에서 거쳐 간 문서) | `.siloroot/state/trail/<세션 id>.jsonl` | 훅이 저절로(읽기, 고치기마다 한 줄) | 새 메시지를 보내면 비운다. 파일은 7일 |
| 턴 기록 | `.siloroot/state/metrics.jsonl` | 훅이 저절로(턴마다 걸린 시간과 토큰) | 계속 |

흔적은 일지에 쓸 재료(그 답에서 읽고 고친 문서)를 이미 모으지만, 새 메시지마다 비워서 하루치로 쌓이지 않는다.

## 생각

- 대화 단위로 남긴다: 세션 이름, 시각, 사용자가 한 말(요청), 한 일, 만지작거린 문서, 정한 것과 안 정한 것.
- AI 기억에 기대지 않고 훅으로 모은다. 사용자의 말은 질문을 보낼 때 훅으로, 읽고 고친 문서는 이미 있는 흔적(`shared/ideas/live-reading-graph.md`)으로 모은다. AI는 그날 일지에 한 줄 요약만 더한다.
- 하루에 한 문서. 홈과 프로젝트에서 한 일을 어디에 모을지는 정해야 한다.

## 아직 안 정한 것

- 사용자의 말을 그대로 남길지, 요약할지(일지가 길어진다).
- 일지를 프로젝트마다 둘지, 홈 한 곳에 모을지.
- 대화 원본(Claude Code의 세션 기록)과 어떻게 이을지.
