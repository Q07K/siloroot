# 완료 조건 검증

- 2026-11-27 외부 AI가 낸 자율 업무 관점 검토에서 나옴. 묶음은 `shared/ideas/autonomous-work.md`

## 외부 의견이 말한 것

- AI가 답을 끝내려 할 때 Stop 훅이 완료 조건을 채웠는지 봄
- 못 채웠으면 끝내지 못하게 하고 이어서 일하게 함. Claude Code가 이런 실행 제어를 지원한다고 함
- 스킬 `/siloroot:evaluate`가 완료 조건을 검증
- 업무 문서의 "완료 조건", "검증 근거" 절에 비춰 봄
- AI가 검증 안 한 일을 완료로 적지 못하게 프로그램이 막음

## 지금 있는 것 (AI, 2026-11-27 확인)

| 무엇 | 지금 |
| --- | --- |
| Stop 훅 | `scripts/metrics-turn.mjs` 하나. 시간과 토큰만 남기고 막지 않음 |
| Stop 훅 입력 | `stop_hook_active` 칸이 들어옴. 테스트(`test/metrics.test.mjs`)가 이 모양으로 흉내 냄 |
| 완료를 적는 곳 | 요구사항 "결과", 결정 "반영", 계획 체크 목록. AI가 마칠 때 손으로 맞춤 |
| 비슷한 아이디어 | 구현 점검(`shared/ideas/implementation-check.md`) |

- 끝내기를 막고 이어 가게 하는 동작은 외부 의견이 든 근거. 구현 전 Claude Code 공식 문서로 확인해야 함
- 막기를 쓰면 끝없이 이어지지 않게 `stop_hook_active`를 봐야 할 것으로 보임(확인 전)

## 구현 점검과 다른 점 (AI)

| | 구현 점검 | 완료 조건 검증 |
| --- | --- | --- |
| 묻는 것 | 약속을 지켰나 | 하기로 한 것을 다 했나 |
| 비춰 볼 문서 | 컨벤션, 설계, 결정 | 업무나 요구사항의 완료 조건 |
| 때 | 요청할 때. 알림은 대화 끝에 | 업무를 마쳤다고 할 때 |

- 결과를 "지켰다·어겼다·판단 못 함"처럼 같은 모양으로 남길 수 있음

## 지난 결정과 부딪히는 곳

- 구현 점검에서 사용자가 정함(2026-11-24)
  - 알림은 기본으로 켜되 막지 않음
  - 막는 관문은 사용자가 고르고, SiloRoot는 거는 법만 문서로 줌
- Stop 훅으로 끝내기를 막는 것은 막는 관문
- 이 결정대로면 기본으로 켜지 않고 사용자가 고르는 쪽

## 생각해 볼 방향 (AI, 정하지 않음)

- 기본은 알림: 완료 조건이 남았으면 대화 끝에 "[SiloRoot] 처리할 일"로 알림
- 막기는 사용자가 자율 루프(`shared/ideas/autopilot-loop.md`)를 켰을 때만
- 스크립트로 볼 조건(테스트 통과, 파일 있음)과 AI가 판단할 조건을 나눔
- "완료로 바꾸려면 검증 근거가 있어야 함"은 막지 않고도 속성 점검 경고로 보일 수 있음

## 열린 질문

- 완료 조건을 어느 문서에 적나: 요구사항 목표, 계획 단계, 업무 객체
- 막는 검증을 둘지. 둔다면 언제만
