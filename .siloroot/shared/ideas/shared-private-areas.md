# 공유 영역과 개인 영역

`shared/ideas/dev-project-use.md`의 첫 덩어리(영역과 모듈)에서 나왔다. 논의 과정은 private/discussions/2026-11-24-sharing-and-versions.md에 있다.

## 무엇이 문제인가

지금은 `.siloroot/` 전체가 git에서 빠져 있다(`.git/info/exclude`). 팀 저장소에서 써도 SiloRoot 문서는 하나도 팀에 가지 않는다. 그런데 한 작업 공간 안에 팀이 봐야 할 문서와 나만 볼 문서가 섞여 있다.

사용자: 팀용과 개인용을 나누는 게 아니다. 같은 SiloRoot를 팀용으로도, 개인용으로도 쓸 수 있어야 한다.

## 비교한 방법

| 방법 | 모습 | 장단 |
| --- | --- | --- |
| 작업 공간 통째로 | 설정 하나로 `.siloroot/` 전체를 git에 올리거나 뺀다 | 가장 단순하다. 팀 저장소 안에서 개인 노트를 따로 둘 수 없다 |
| 공유 영역과 개인 영역 | 공유 문서는 git에 올라가는 폴더에, 개인 문서는 빠지는 폴더에 둔다. 모듈마다 기본 자리가 있다. 뷰어는 둘을 함께 읽고 서로 연결한다 | 팀과 개인을 한 작업 공간에서 같이 쓴다. 영역을 나누는 규칙과 뷰어 수정이 필요하다 |
| 문서마다 속성 | 프론트매터에 공개 범위를 적는다 | git은 속성을 보고 파일을 빼지 못한다. 실수로 개인 문서가 올라갈 위험이 크다 |

## 정한 것

**2026-11-24, 사용자:** 공유 영역과 개인 영역으로 나눈다.

| 문서 | 기본 자리 |
| --- | --- |
| 컨벤션 | 공유 |
| 결정 기록 | 공유 |
| 작업 지식(에러 원인 등) | 공유 |
| 개인 공부 노트 | 개인 |
| 아이디어 메모, 뷰어 댓글, 사용자 정보 | 개인 |

개인 영역의 문서도 사용자가 "팀 공개로 아카이브"하면 팀이 볼 수 있다. 그 방법은 `shared/ideas/publish-copy.md`에 있다.

AI 제안 배치(아직 정하지 않음):

```
.siloroot/
  shared/    git에 올라감
  private/   git에서 빠짐
```

## 열린 질문

- 공유 영역의 실제 폴더 이름과 위치.
- 공유 문서가 개인 문서를 가리킬 때 팀원에게 끊긴 연결로 보이는 문제를 어떻게 막을지.
