# 세션 사이 인수인계

- 2026-11-26 외부 제품 피드백(이탈 원인 가설) 검토에서 나옴
- 피드백의 P0 "세션 간 업무 자동 인수인계"에 P1 "미해결 업무 자동 추적", "과거 업무 기반 다음 행동 제안"을 묶음
- 셋 다 "새 세션이 하던 일을 알고 시작하나"라는 한 관심사

## 피드백이 말한 것

| 기능 | 기대 효과 |
| --- | --- |
| 세션 사이 인수인계 | 어제 하던 일을 다시 설명하지 않아도 됨 |
| 남은 일 자동 추적 | 놓친 일이 줄어듦 |
| 지난 일로 다음 할 일 제안 | 무엇을 할지 고민하는 시간이 줄어듦 |

## 지금 있는 것 (AI, 2026-11-26 확인)

| 무엇 | 지금 | 빈 곳 |
| --- | --- | --- |
| 한 일 | 작업 일지(개인 영역, 하루에 한 문서)에 AI가 마칠 때 한 줄씩 씀 | 새 세션이 읽는다는 보장 없음 |
| 남은 일 | 확인할 것 장부(개인 영역), 로드맵 "지금" 칸 | AI가 손으로 더하고 지움. 끝난 줄이 남아 있기도 함 |
| 세션 시작 훅 | `viewer/notify.mjs --session`이 처리할 일(피드백, 후보, 웹 편집)과 업데이트만 알림 | 일지, 확인할 것, 로드맵을 넘기지 않음 |
| 읽게 하는 규칙 | 관리 블록 "코드 열기 전에 로드맵과 결정 먼저 보기" | 규칙에만 기댐. 읽었는지 안 보임 |

## 생각해 볼 방향 (AI, 정하지 않음)

- 세션 시작 훅이 짧은 인수인계를 넘김
  - 예: 마지막 일지 몇 줄, 열린 확인할 것 수, 로드맵 "지금" 칸
  - 매 세션마다 붙으므로 줄 수에 상한을 둠. 길면 토큰 부담과 부딪힘
- 남은 일 정리
  - 끝난 줄을 자동으로 가려내기는 어려움
  - 일지에 같은 일이 끝났다고 적힌 줄을 후보로 보이는 정도
- 다음 할 일 제안
  - 새 판단을 만들기보다 로드맵 "지금" 칸과 열린 질문에 이미 적힌 것을 모아 보임
  - 목표와 지금 상태 사이 빈 곳에서 새 일을 찾는 쪽은 업무 발견(`shared/ideas/task-discovery.md`, 2026-11-27)

## 열린 질문

- 훅이 넘길 양과 모양
- 같은 작업 공간에서 세션 여럿이 함께 돌 때 어느 세션의 일을 넘길지
- 인수인계가 쓰였는지 어떻게 알지: `shared/ideas/usage-metrics.md`
