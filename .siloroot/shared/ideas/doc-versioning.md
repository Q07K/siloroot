# 문서 버전 관리

`shared/ideas/publish-copy.md`에서 "공개한 뒤 원본이 바뀌면 어떻게 하나"를 묻다가 나왔다. 논의 과정은 private/discussions/2026-11-24-sharing-and-versions.md에 있다.

## 정한 것

**2026-11-24, 사용자:**

- 과거 내용은 과거 버전 파일로 남긴다. 실제 파일은 버전마다 따로 있다.
- 웹 뷰어에서는 문서 하나로 보인다. 그 문서 안에서 버전을 바꿔 보고, 두 버전을 비교(diff)해 본다.
- 문서 목록의 항목에 버전이 표시된다.
- 범위는 공유 영역 전체(컨벤션, 결정, 작업 지식, 공개본)다. 아래 비용 줄이기 방안을 함께 둔다.

## 배치

AI 제안이다. 다른 문서가 가리키는 경로는 버전이 바뀌어도 그대로여야 하므로, 최신본은 늘 같은 경로에 두고 지난 버전만 옆 폴더에 쌓는다.

```
shared/decisions/
  payment-module.md            최신본. 다른 문서는 늘 여기를 가리킨다
  payment-module.versions/
    v1.md
    v2.md
```

뷰어에는 이미 줄 단위 비교 코드(`viewer/diff.mjs`)가 있어서 버전 비교에 그대로 쓸 수 있다.

## 비용 줄이기

사용자가 토큰 사용과 문서 수를 걱정해서 붙인 방안이다. 이 방안까지 함께 확정했다.

| 걱정 | 줄이는 법 |
| --- | --- |
| AI가 지난 버전까지 읽어 토큰을 쓴다 | 평소에는 최신본만 읽는다. `*.versions/` 폴더는 검색에서 빼고(`.ignore`), "그때 왜?"를 물을 때만 연다 |
| 버전을 만들 때 AI가 문서를 다시 쓴다 | 버전 만들기는 스크립트가 파일을 복사하는 일로 둔다. AI가 본문을 다시 출력하지 않으니 토큰이 거의 들지 않는다 |
| 고칠 때마다 버전이 생긴다 | 정해진 경계에서만 만든다. 결정이 `바뀜`이 될 때, 컨벤션 규칙이 바뀔 때, 공개본을 다시 낼 때. 대부분 문서는 v1에 머문다 |
| 화면과 목록이 문서로 넘친다 | 지난 버전은 `*.versions/` 안에 숨고, 뷰어는 문서 하나로 묶어 보인다 |

## 고르지 않은 길

git 기록을 버전으로 읽는 방법. 파일은 늘지 않지만 git에 의존하고, git에 올라가지 않는 개인 영역에는 쓸 수 없다. 실제 파일이 버전마다 있어야 한다는 사용자 뜻과도 다르다.
