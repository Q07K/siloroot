# Codex에서 SiloRoot 쓰기

## 문제

Codex에서 SiloRoot 스킬을 읽을 수 있어도 Claude Code용 훅으로는 Codex에서 문서를 읽고 고친 흔적을 보기 어렵다. 재현과 원인은 `shared/issues/codex-support-missing.md`에 있다.

## 첫 단계

이미 만든 SiloRoot 작업 공간에서 Codex의 셸 읽기와 패치 흔적을 지금 쓰는 연결 그래프에 보인다. 새 메시지를 보내면 현재 세션의 흔적을 비운다. Claude Code가 남긴 흔적과 Codex가 남긴 흔적은 같은 형식을 쓰고 세션 파일은 따로 둔다.

| 확인할 것 | 성공 기준 | 확인 방법 |
| --- | --- | --- |
| 설치와 등록 | Codex가 SiloRoot 플러그인과 두 흔적 훅을 찾는다. 신뢰 검토가 필요한 상태를 표시한다 | Codex CLI에서 테스트용 설치 후 훅 목록 확인 |
| 문서 읽기와 패치 | 셸에서 읽은 문서는 읽기로, 패치한 문서는 편집으로 기록된다. 기존 문서 범위 규칙을 따른다 | 등록 명령으로 훅 이벤트를 보내 실제 JSONL 확인 |
| 새 메시지 | 현재 세션의 흔적을 지우고 다른 세션의 흔적은 남긴다 | 읽기·패치·초기화를 같은 세션으로 실행 |
| 기존 사용 | Claude Code의 훅 정의와 뷰어의 흔적 읽기 흐름이 계속 동작한다 | 기존 훅·흔적 테스트 실행 |

## 더 조사할 것

| 범위 | 확인할 것 |
| --- | --- |
| 설치와 업데이트 | 데스크톱과 CLI의 설치·업데이트·새 세션 흐름, 캐시 버전 교체, 새 훅 검토, `/siloroot:update`가 관리할 대상 |
| 초기화와 규칙 | Codex에서 초기화를 실행하는 방법, `AGENTS.md`로 관리 규칙을 읽는 방법, 기존 Claude Code 작업 공간과 같이 쓰는 경우 |
| 뷰어와 알림 | 세션 시작 시 프로젝트와 홈 뷰어를 자동으로 열지, 피드백·후보·업데이트 알림이 Codex에도 전달되는지 |
| 기록 범위 | `functions.exec` 안의 셸과 패치는 Windows Codex CLI의 도구 묶음 방식에서 확인했다. 파일 MCP와 서브에이전트의 지원 범위도 확인한다 |
| 턴 기록 | Codex `Stop` 이벤트와 대화 기록에서 세션·턴·토큰을 가져올 수 있는지, Claude Code와 어떤 단위까지 비교할 수 있는지 |
| 작업 공간 | Windows와 macOS/Linux, Git worktree, 홈 문서, 초기화하지 않은 폴더에서 권한과 문서 경로가 맞는지 |

## 결과

- Codex CLI 0.170.0(Windows)에서 기존 SiloRoot 마켓플레이스로 분리된 임시 프로필에 설치했다. 셸·패치 훅과 새 메시지 초기화 훅이 등록됐고, 둘 다 신뢰 검토 대상으로 표시됐다.
- 등록 명령에 이벤트를 넣어 문서 읽기와 문서 추가가 각각 기록되는지 확인했다. 이름에 공백이 있는 추가 문서와 현재 세션만 초기화하는 경우를 포함했다.
- 흔적 테스트 23개가 통과했다. 전체 테스트는 252개가 통과했다. 포트 테스트 한 개는 실행 중인 뷰어가 4180을 쓰고 있어 실패했고, 변경하지 않은 설정 코드와 테스트로도 같은 실패를 재현했다.
- 임시 프로필의 실제 Codex에서 로컬 응답 서버로 도구 묶음 한 번을 실행했다. 하위 셸과 패치가 각각 훅으로 들어왔고, 뷰어의 `/data`에 새 문서가, `/trail`에 읽기와 편집이 차례로 나왔다.
- 같은 테스트 세션을 이어 새 메시지를 보내니 그 세션의 흔적만 비워졌다. 다른 세션의 파일은 그대로였고 뷰어도 비워진 흔적을 돌려줬다.
- 문서 흔적 지원을 `0.8.3`으로 `main`에 합쳤다. 데스크톱에 새 버전을 설치한 뒤 신뢰 검토와 새 세션에서의 적용을 확인한다. [PR #37](https://github.com/Q07K/siloroot/pull/37)
